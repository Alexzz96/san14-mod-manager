# 基本页原生累计战绩

将武将详情基本页的任务、目标、期间三行替换为模组累计战绩，并以相同原生资源向下增加三行。

| 行 | 显示 | 数据含义 |
|---|---|---|
| 1 | 杀敌总数 | enemy_loss，包含伤兵 |
| 2 | 击溃部队 | units_routed |
| 3 | 自身覆灭 | units_defeated，自身部队覆灭次数 |
| 4 | 兵力损失 | own_loss，自身累计兵力损失 |
| 5 | 击伤武将 | officers_injured |
| 6 | 军功 | 当前可消费余额，见 OFFICER_MERIT.md |

沿用现有 battle_stats 存档统计口径：从模组接入后累计，不补算过去战斗；新战绩仍需保存游戏。`已绑定存档` 不表示最新战绩已经写入存档。未采集和有效零值分别显示。该改动不改变武将实际任务、游戏属性或存档。

## 原生接入

`CInfoDetailPerson` 基本页 vtable RVA 0x1381700。刷新 0x80a220 执行原逻辑后覆写原生文字节点 91/92、96/97、101/102。原始页资源 `11_01_02_00_info_busho0` / 0x802ce759 含 105 个节点。

下方三行通过独立原生 CCmnLayoutWidget 加载同一资源，保留根节点 0、55、87 及任务三行子树 88..102，隐藏其他所有节点。相对基本页下移 120 个游戏坐标单位，保持 40 单位原生行距。文字、背景及字体设置均由游戏资源提供，没有自绘窗口、借用图形指针或修改共享资源。

UI 线程负责控件创建、刷新、注册和释放。统计工作线程经 SRWLOCK 发布数值副本；UI 只接受页面、人物和世界均匹配且不超过 1.5 秒的副本。切换人物立即清除旧数值。退出页面注销绘制，销毁前清理附加资源；分配失败保留原任务行和顶部战绩条。

基本页成功接入时隐藏顶部重复战绩条；能力、列传、科技树页继续保留原战绩条。现有新增入口默认第四页及地图返回流程保持原实现。

## 验证

`test_basic_stats` 覆盖 30 次创建、显示、隐藏和释放，分配/资源初始化失败、武将与世界隔离、有效零值与缺失值、原生节点可见范围、重复隐藏和释放顺序。`verify_native.py` 检查六个 hook 入口和原生资源容器 ABI。离线测试不能替代游戏内视觉验收。

手动检查：基本页出现六行、字体背景对齐且无重复条；切换人物无串数据；切换四个标签无残留；关闭再开及返回地图正常；1080p、高分辨率、窗口模式无重叠。杀敌总数含伤兵。

## v2 可见性修正

首版游戏实测仅显示原三行。附加容器调用原生注册函数 0x77c0e0，但漏掉了独立的可见性设置。v2 在注册后调用 0x789820(extra,1)，在注销及释放前调用同一接口隐藏。回归测试分别检查注册状态和可见状态，覆盖重复切换、构建失败与销毁。实际画面仍需手动验收。

## v3 小地图入口显示顺序

v2 部分入口成功，小地图进入基本页仍只有三行。只读运行快照确认原页面与附加容器 flags 均为 0xf，节点数均为 105，附加行变换正确下移 120；活动 UI 注册列表中附加容器为第 483 项、原页面为第 525 项。该路径先刷新并注册附加行，再显示原页面，导致附加行位于原页面背景之前。

show_hook 不再因 active 为真而跳过附加容器注册：先隐藏并注销此前注册，再调用原页面 show，最后注册并显示附加行。回归测试模拟 refresh-before-show 及连续 show，断言只保留一个有效注册且附加容器顺序始终晚于父页面。仍需从小地图和新增菜单分别进行游戏内验收。
