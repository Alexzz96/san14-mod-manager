# 词条特殊能力与击退设计草案

更新：2026-10-10。状态：通用框架与插件击退仍为讨论稿；黄忠闪袭已接入默认关闭的测试实现，实机待验收。本文不修改基础编辑框架的范围和验收状态。

## 可行性结论

词条和插件兵种可以作为特殊能力的载体。现有框架已经有活动部队身份、效果描述、属性适配、战斗观察及存档绑定，可以继续扩展。现有 `S14TroopEffect` 只支持已登记的减伤、状态免疫和包围免疫类型；目前没有击退类型，也没有完成插件接入及实机验收的部队位移执行接口。把 `knockback` 写进配置不会自动生效。

2026-10-10 追加：从用户提供的当前 EXE 已静态核对 `.sp5push` 的长枪击退链，包含相邻目标后推一格、阻挡时补混乱、占位与路径处理，见 [长枪击退逻辑证据](LONG_SPEAR_KNOCKBACK.md)。因此位移接口已从“待定位”推进到“静态调用已核对”；安全时机、完整副作用与词条接入仍待验证。下文的 20% 概率、冷却和阻挡不补效果是未来插件样本的设计选择，并非此 EXE 现有规则。

用户进一步提出位移背刺，并明确多格表示“沿敌军后方逐格找落点”。通用规则保存于 [闪袭 / 位移背刺](BLINK_BACKSTAB_DESIGN.md)。`0.11.0-dev.3` 已接入仅黄忠主将部队的测试实现：依次检查敌军后方第 1、2、3 格，移动来源；下一笔对原目标的合法普通直击 +30%，冷却 5 游戏日，默认关闭。见 [测试实现与验收](HUANG_ZHONG_BLINK_TEST.md)。静态接口与独立测试已核对，真实游戏多格位移仍待验收；通用 JSON 能力框架及插件击退仍未实现。

这里暂按“攻击后把敌军向远离攻击方的方向推一格”理解击退。它与下达撤退命令、降低士气、造成止步是不同能力，不用一种效果冒充另一种。

官方 PK 手册说明了撤退命令、三种异常状态和兵站效果；当前 EXE 的击退调用证据来自本地静态分析，不能从手册推导。
参考：[出征、战法、异常状态与兵站](https://www.gamecity.com.tw/manual/sangokushi14/wpk/5100.html)。

## 可设计的能力家族

| 家族 | 示例 | 当前接入条件 |
| --- | --- | --- |
| 持续属性 | 重甲提高防御、轻骑提高机动 | 已有属性适配，可复用；具体兵种仍需验收 |
| 条件属性 | 残兵奋战、平原冲锋、孤军坚守 | 需确认条件读取和计算层，避免反复叠乘 |
| 防护与抵抗 | 抗混乱、包围免疫、抗击退 | 前两类已有适配；抗击退只在未来插件位移规则内预留，不能宣称抵抗未知原生效果 |
| 攻击附带效果 | 压制士气、短时破甲、战法后追击 | 需确认攻击完成事件、来源、状态更新与到期清理 |
| 战场位移 | 击退、拉近、交换位置 | 当前 EXE 击退链已静态定位；完整副作用和运行时接入需验证，拉近和交换没有相同验证结论 |
| 条件触发恢复 | 击溃敌军后恢复士气或部分兵力 | 需核对击溃归属、恢复入口、伤兵与统计口径，不等于直接增加士兵字段 |

兵种定义说明“拥有能力”；一次出征绑定决定“本队当前拥有能力”；战斗事件决定“何时触发”；效果适配决定“怎样改变状态”。界面名称和光圈只展示结果，不能充当效果执行。

建议把通用效果能力作为公共组件，供插件兵种和插件词条引用，避免给每一种兵种分别复制触发、冷却和存档代码。原生个性定义目录继续只读；插件能力使用独立字符串 ID，不占用猜测的原生隐藏编号。现有 AI 词条抽取规则保持原样，后续是否挂载新能力另行决定。

## 击退首个实验样本：破阵

以下数值仅是便于测试的起点，尚未定案：

| 项目 | 草案规则 |
| --- | --- |
| 触发 | 本队对相邻敌方陆上战斗部队完成一次普通攻击，实际扣兵大于零，且目标仍存活 |
| 概率 | 每次符合条件的完整攻击 20%，不是每一笔扣兵或每一帧抽取 |
| 距离 | 向远离攻击方的合法相邻格推一格 |
| 冷却 | 来源部队成功触发后 5 个游戏日；游戏时间单位与推进节点仍需核实 |
| 连续控制 | 目标成功被击退后 3 个游戏日内不再被此类插件击退；具体平衡数值待测试 |
| 目标范围 | 首个样本只考虑陆上战斗部队；据点、建筑、水军和运输队暂不参与 |
| 阻挡 | 目的格被占用、地形不合法、边界越界或位移接口不可用时不位移 |
| 失败结算 | 首版实验建议不补伤害、不强加混乱，也不消耗成功冷却；同一攻击事件仍登记已处理，不能反复抽取 |
| 连锁 | 被推部队不继续推动其他部队，击退本身不触发第二次击退或额外攻击 |

“向后”要以攻击方和目标当时的格子确定。六角格方向、相邻关系及并列候选的选择方式需要验证，不能用棋格编号简单加减模拟。第一版可采取保守规则：只有明确的后方合法格才执行，其余不触发位移。

首轮测试时把概率设为 100% 或 0%，分别验证执行与不执行；确认正确后再验证概率和冷却。限制推一格已经会影响接敌、包围和兵站，需要单独做平衡测试。

## 击退为什么需要新的底层接口

不能只写活动部队的 tile 字段。必须核实并整体处理：

1. 部队原位置、目的位置及棋格占位的一致性。
2. 合法地形、移动中的路径、目标及移动动画/显示状态。
3. 新位置下的交战邻接、连携、包围和兵站重算。
4. 位移是否触发占领、陷阱、火烧、渡水或额外消耗；不能误复用普通行军的整条费用和事件链。
5. 保存重启与旧档回退，以及部队移除和编号复用。

击退不改玩家或 AI 的既定命令；位置变动后的路径需要通过核实的原生处理重算。不能使用“让 AI 撤退”来实现推一格，也不新增 AI 决策开关。

战斗 hook 只确认并记录触发意图。真正的位移必须放在已经证明安全的本次进军结算点，避开仍在使用旧占位的攻击调用栈。人物编辑的“下次规划回调”不能直接作为战斗击退的执行时机，否则效果可能延迟整个回合。

## 公共效果框架应预留的内容

- 定义：能力 ID、效果类型、触发类型、目标筛选、概率、冷却、参数、叠加规则及所需原生能力。
- 事件：真实来源、目标、完整攻击/战法关联编号、结算前后状态、游戏时间、会话；来源无法核实不触发。
- 身份：会话、规范部队对象、编号、主将、序号和出征绑定，避免旧队伍的冷却转移给复用编号的新队伍。
- 状态：来源冷却、目标抵抗窗口、去重记录；冷却使用游戏时间，不能用电脑经过的毫秒数。
- 执行：先验证全部关联对象和目的格；在安全结算点再次核对；调用完整原生操作，复读全部关键状态。失败记录具体原因，不报完整成功。
- 随机：能力触发独立维护随机状态，不消耗游戏随机，也不改变现有 AI 出征词条抽取和城市保底序列。
- 持久化：成功保存时绑定正确存档；恢复冷却与随机状态；回退旧档同步回退。具体附属文件或旧文件版本迁移方案待接口实现后确定，不能直接修改现有格式。
- 能力状态：定义可登记、触发来源已核实、执行已接入、独立测试通过、实机验收通过分别记录；缺少位移能力时只停用击退。

现有战斗采集会记录攻击尝试和多笔子效果，不能把尝试等同于成功攻击，也不能把正数扣兵统一当成普通攻击。伤害归属、连携战法、火烧、补兵和重复回调需要明确区分。显示属性 getter 会在编成预览和查询中反复调用，不能在那里抽取击退概率或施加状态。

## 接口研究顺序与验收

1. 基于已定位的长枪移动/占位/路径调用链，继续确认当前 EXE 的具体参数、线程和副作用；没有证据的部分保持未知，先核对与 EXE 既有击退的触发重叠。
2. 核对普通攻击“完成一次”的稳定边界和来源/目标，覆盖现有改写的直接交战路径，不改变战绩采集口径。
3. 用独立模型验证相邻格规划、占位阻挡、重复事件、冷却、目标抵抗、编号复用、关闭取消与存档回退。
4. 接入一个可控制的单目标样本，再实机验证两队对战、移动中的目标、多人围攻、地图边缘和狭道阻挡。
5. 核对路径、连携、兵站、火烧/陷阱、占领与保存重启；出现占位不一致时停用对应能力，不能让后续效果继续执行。
6. 最后接入词条展示与概率平衡；范围击退、连续推动和强制追击作为后续设计，不作为首个样本。

当前判断：当前 EXE 已存在真正击退，具备抽取通用位移能力的具体研究基础；插件词条击退尚未实现或验收。击退作为独立实验能力推进，不阻塞基础武将编辑框架。
