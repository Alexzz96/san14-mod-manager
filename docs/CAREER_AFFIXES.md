# 战绩词条与武将称号可行性

2026-10-09。根据当前本地 0.9.6 源码和游戏可执行文件的离线反汇编分析。此文是设计和接入评估，没有修改游戏内存、姓名、配置、DLL 或安装包，没有上传 GitHub。

用户希望特殊能力成为词条，通过战绩获得；允许修改武将本名。具体例子为“百战精锐”：已记录斩敌量达到 5000，名称显示为“战-曹仁”，数值提高。示例增幅沿用当前已验证的攻军、防御 +10%。

## 可复用基础与尚未完成的部分

| 部分 | 当前证据 | 待实现 |

| 数值效果 | `army_buff.c` 已在真实攻军、防御计算中将曹仁队的实际结果乘 1.10 | 移除限定 518 的资格判断，按词条缓存支持不同武将和效果分组 |
| 武将姓名 | 原生姓名字段、姓名格式化入口及部队名拼接链已静态定位 | 确认调用语义、缓冲区约束和各界面的改名覆盖范围，接入后实机核对 |
| 地图视觉 | 0.9.6 的曹仁光圈和悬浮说明已实机确认可用 | 通用多部队绘制、主称号颜色、全部词条说明 |
| 存读档 | 已有按游戏存档哈希绑定的生涯检查点 | 读档清空旧资格缓存并重新派生；有选择或时限的状态扩展检查点 |

斩敌口径是已经记录的敌方兵力减少，包含伤兵，不是实际阵亡人数。采集之前或关闭期间没有数据，不能补算为历史战绩。资格说明应明确使用“已记录斩敌量”。

## 第一条完整规则

| 字段 | 规则 |
| --- | --- |
| 稳定 ID | `veteran_elite` |
| 词条名称 | 百战精锐 |
| 称号前缀 | 战 |
| 条件 | 当前存档分支中该武将 `enemy_loss >= 5000` |
| 持有者 | 武将编号，而不是姓名字符串、部队指针或出征编号 |
| 作用部队 | 持有者担任主将的有效部队；第一版副将不传播增幅 |
| 武将显示名 | 战-曹仁 |
| 部队显示名 | 战-曹仁；若某界面保留原生后缀，则为战-曹仁队，取消后缀须处理部队名拼接层 |
| 实际效果 | 原生实际攻军、防御结果乘 1.10，白字基础值维持原计算 |
| 展示 | 主称号前缀、头像光圈、悬浮词条名称/条件/进度/效果，详情解析列出插件贡献 |
| 激活时机 | 已确认事件经工作线程累计后刷新资格；首版在回合结束后统一解锁，下回合生效，避免结算中途反馈造成不可控连锁 |
| 回城再出征 | 词条跟随武将，重新绑定新部队 |
| 读档 | 从该存档的生涯检查点派生；读取达标之前的旧档时取消资格，不沿用未来分支 |
| 关闭功能 | 停用效果和显示，不删除已记录战绩；重新开启后按当前记录重算 |

最后一行定义的是词条模块开关。战斗采集开关决定后续能否继续累计；已经从当前有效检查点取得的资格不应仅因暂停采集而自动消失。

目前曹仁 +10% 是无战绩门槛的测试能力。迁移后应由同一效果项接管，不同时保留测试加成与词条加成。未达到 5000 时不会自动继承测试能力。

## 原生姓名与部队名称代码链

对应 EXE SHA256：`98fe94d8495f75c4540182949a05a42d87ce9e8c5d6e50175e401cb78cc295e9`。以下都是模块相对地址，仅作为当前样本证据，不能推断其他游戏版本同地址。

- 武将结构 `+0x12` 与 `+0x24` 为两段固定长度 UTF-16 姓名；当前武将一览直接读取这两段再拼接。不能无界追加称号或对反复读取的已加前缀字符串再次加前缀。
- `0x20c270` 从这两段姓名组织输出；离线可见 `%s%s` 格式、调用原生格式化函数 `0x1885c0`。这是姓名格式化的候选接入点，不等于所有姓名使用方已覆盖。
- `0x20bec0` 从部队 `+0x12` 的主将编号取武将对象，调用 `0x20c270`，再进入 `0x2d4310` 拼接层。
- `0x2d4310` 根据传入字符串和本地化资源组织输出，包含资源编号 `0x352` 的路径；资源文本及最终输出须在实机绑定时核对。
- 悬浮部队基础信息更新链 `0x829090 -> 0x8256a0 -> 0x821400`，其中 `0x821400` 调用 `0x20bec0`，随后把结果提交到原生文本节点（`0x831e70`）。这提供了窄范围队名替换的候选路径。

离线记录位于本地分析目录 `E:\314 mod\analysis\career\affix-feasibility`，包含函数反汇编及验证过的直接调用引用。此次没有执行这些原生函数或安装新的姓名钩子。

### 推荐姓名处理

优先在姓名/队名格式化时生成带称号的显示名。用户允许改武将名，所以可将武将详情、部队和插件列表统一显示“战-曹仁”；保留稳定编号与原始姓名，搜索原名、拼音仍命中。插件直接读取原始字段的页面需要调用同一个称号格式化接口，不能只修改游戏原生显示而漏掉 F 武将一览。

真正改写原生姓名字段也是一种方向，但它会成为存档内容，并可能影响势力名称、人物介绍和其他直接读字段的界面，需要原名备份、关闭后的恢复、固定字段容量和存读档行为验证。第一版显示称号可在关闭后恢复，不必把词条写进游戏存档姓名字段。

原生部队后缀和各界面称号是否完整出现仍需实机验证，不把静态代码定位当作改名效果已经验收。

## 词条分型与组合

每条词条独立包含：ID、显示名、前缀、获得条件、持续资格、作用对象、效果集合、叠加分组、优先级、等级/升级组、视觉配置、规则版本。

| 类型 | 条件来源举例 | 效果方向 | 接入阶段 |
| --- | --- | --- | --- |
| 战绩成长 | 已记录斩敌量、击溃次数、单挑制胜次数、已核实擒获次数 | 攻军、防御、称号等级 | 攻防入口可复用；其他指标按核实口径使用 |
| 战场条件 | 当前士气、兵力比例、阵形、地形 | 条件性攻防增幅 | 资格及失效规则需实现 |
| 护军光环 | 战绩解锁后，两格内友军 | 邻军攻防、其他范围效果 | 范围对象、来源、去重尚未实现 |
| 异常防护 | 词条已获得，并对指定状态生效 | 免疫、抵抗或解除 | 指定状态及真实施加路径需专项验证 |
| 恢复与保护 | 已记录战绩解锁，每旬或受击触发 | 伤兵恢复、士气保护、直接减伤 | 结算入口、上限、守恒及顺序尚需定位验证 |

解锁条件与实际效果分开配置，例如单挑达到门槛可以奖励防御，不必强行把奖励效果绑定到触发指标名称。光环、减伤、免疫、伤兵恢复、士气不掉落可成为词条，但目前只是设计方向，不能把观察到的字段当成已经验证的修改接口。相关边界见 [进阶效果设计](SPECIAL_EFFECTS_ADVANCED.md)。

一个武将可以持有多条词条，姓名只显示一个主前缀，避免“战-御-勇-曹仁”越变越长；悬浮显示所有已获得及当前生效词条。相同升级组仅取最高等级。同类属性加成先汇总后只乘一次，并设总上限；例如 +10% 和 +5% 定义为 +15%，而不是迭代乘 1.10 和 1.05。减伤、免疫、治疗分别定义自己的规则。

## 缓存和持久化边界

生涯累计目前是工作线程数据，`s14_stats_row` 明确为 worker-thread-only。不能在原生属性计算或 DXGI Present 回调里读取全武将表、扫描磁盘、解析配置或遍历生涯日志。

工作线程在载入完成、确认回合结束、规则/开关改变时生成有界、可并发读取的资格与效果缓存，原生计算只做身份校验及缓存查询。缓存需要包含当前存档分支和版本；开始载入时先失效，载入成功后重新建立，失败时也不能把别的分支资格带进当前世界。光圈、姓名、悬浮说明、数值解析都读取同一生效状态。

“已记录斩敌量达到门槛”的自动词条可直接从存档战绩派生，无需再次永久保存一份重复计数。若允许玩家选择主称号、手动装备词条、临时期限或保存解锁日期，需要在插件的存档检查点中扩展对应状态，随旧档回退。

## 第一版验收

1. 4999 不达标、5000 恰好达标；同一事件不重复累计，不从名称解析资格。
2. 解锁后的名字、光圈、说明和实际攻防一致；当前 +10% 测试能力不另加一层。
3. 曹仁和另一名武将均能独立达标；未达标的同名武将不受影响。
4. 比较真实攻击/受击路径与界面值，反复悬浮、开关和打开详情均不重复增幅。
5. 普通/自动存档、重启、回读达标前旧档、新档、回城再出征和更换势力均正确绑定。
6. 姓名缓冲容量、长名字、部队后缀、原名/拼音搜索以及关闭后显示恢复均核对。

建议先做“百战精锐”一条全流程，再通过配置加入更多词条。当前结论是有明确实现路径；通用词条系统和称号改名尚未实施。
