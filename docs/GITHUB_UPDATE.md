# GitHub 在线更新

0.7.2 起，“安装与状态”提供“检查 GitHub 更新”和“下载并更新”。检查由用户点击触发，不在后台轮询。游戏内 F10 的检查入口打开独立管理器，网络访问在独立程序后台线程中进行，不阻塞游戏结算。

更新源固定为 [Alexzz96/san14-mod-manager](https://github.com/Alexzz96/san14-mod-manager/releases)，无需登录、Git 或 Python。比较最近十条已发布版本的 `v主版本.次版本.修订版本`，包括预发布版，选择版本号最高且安装器有效的发布；忽略草稿、较旧版本及源码附件。

1. 打开“安装与状态”，点击“检查 GitHub 更新”。
2. 如果发现新版本，保存并完全退出游戏，确认游戏目录正确。
3. 点击“下载并更新”。后台下载独立安装器并核对发布附件的大小和 GitHub SHA-256 摘要。
4. 校验成功后关闭旧管理器并打开新版安装器，执行原有安装流程；成功或失败均显示提示。游戏运行时禁止替换；文件占用、权限及网络失败可重试。
5. 重新启动游戏。更新保留配置、游戏存档与战绩检查点；新安装的墙体 5 格限制默认关闭。

连接 GitHub 受限时，可以从发布页手动下载 `SAN14ModManager-版本-windows-x64.zip` 或 `.exe`；两者包含相同安装器。旧版首次升级需要手动下载安装包，之后可使用在线更新。

下载只使用 HTTPS，不接受跳转到 HTTP；文件大小限制为 32 MiB。地址必须对应本项目的版本与独立安装器，摘要缺失或不匹配时不执行，失败下载会删除。成功下载的安装器位于当前用户临时目录，以 `S14` 开头的独立 EXE 保存；它不属于游戏目录的卸载范围，可以通过系统临时文件清理移除。GitHub 摘要用于下载完整性核对，不是独立的代码签名。

发布维护：上传 `SAN14ModManager-版本-windows-x64.exe`、同版 ZIP 与 `SHA256SUMS.txt`，确认附件状态为 `uploaded` 且 GitHub 提供 SHA-256 `digest`，最后公开发布。不要只上传 GitHub 自动生成的 Source code 文件。

后续版本可通过版本标签自动发布：修改 `VERSION` 与 `native/features.h` 中的版本、补充变更记录，提交后推送同名 `v版本` 标签。`release.yml` 会校验标签、构建、测试、打包，上传并核对所有附件后公开预发布版。单纯推送源码提交不会生成可安装更新；测试失败时不会公开不完整的发布，已有公开附件也不会被覆盖。
