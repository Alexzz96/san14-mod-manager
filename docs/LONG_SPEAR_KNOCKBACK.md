## 样本与结论

- 文件：`E:\san14\THOP_v2.1\SAN14PK_SC.exe`，33,249,792 字节。
- SHA-256：`604f5fe9bdd6dc2b813b93333aabeadefbad50afd2b4f71a11718b7363bca8ef`。
- PE 首选映像基址：`0x140000000`。下文地址均为 **RVA**；运行地址必须使用实际加载基址加 RVA，不能当成文件偏移。

此文件的追加代码段 `.sp5push` 已有有效兵种编号 5 的击退实现：从结算对象列表收集来源及目标，规划相邻敌对部队向后移动一格；目的格受阻时转入混乱分支。项目 `native/troop_registry.c` 将兵种 5 映射为“长枪”，该中文名称来自项目已有映射；EXE 内两处 `cmp eax,5` 则是直接机器码证据。

这是**当前修改版 EXE 已有的扩展**。没有对比官方原版，不能据此认定它是官方原生长枪能力，也不能仅凭节名确定作者。

## 来源筛选与触发边界

收集入口 `0x248227B` 调用 `0x15F6E0` 取得容器，检查两组链表的节点范围、容量和链接。来源节点需要满足：

1. 节点 `+0x04` 类型值为 `27`；`+0x14` 的字节值大于 `1`。**这两个字段的业务含义尚未知**。
2. 节点编号可解析为当前世界中的规范部队对象，编号范围 `1..500`，兵力非零，相关有效标记及 `0x2107B0` 检查通过，节点棋格与部队棋格一致。
3. `0x208BB0(army)` 返回 `5`：在 `0x24823DF`、执行前 `0x2482574` 两处再次核对。
4. `0x293BF0(army,55)` 返回 `0`。这是对**来源部队**主将个性类别的查询；该排除条件与击退的设计意图未确认，不能命名为“目标抗击退”。
5. 来源对象尚未登记为已处理。候选节点必须指向该来源节点，类型为 `27`，目标编号和棋格匹配规范部队；同一来源的目标去重，最多保存 `6` 个计划。

`0x208BB0` 根据当前所在棋格的地形资料选择部队 `+0x1B` 或 `+0x1C` 字段，因此筛选的是**当前位置下的有效兵种 / 阵形**，不是直接固定读取陆上编号。

此路径按容器结算批处理触发，不能写成“每次普通攻击必触发”或“每笔伤害都有概率触发”。已分析的击退代码中未见概率抽取或游戏日冷却；但来源节点条件和原有结算节点仍未完整解释，不能由此认定玩家可见触发率为 100%。

来源去重表在 `CProgressState` 初始化包装成功时清空，在关联对象清理时移除相应记录。一组计划中至少有一次成功后保留来源记录；全部无效果时清除该记录，执行故障时终止本批。它不是已经证实的“每次攻击冷却”或“每个批次清空”。具体每回合次数需要观察状态初始化及调用时序。

## 一格击退的规划

`0x2482960` 的静态参数形式为 `(RCX=来源部队, RDX=目标部队, R8=输出计划)`，返回 `1` 表示可形成计划、`0` 表示拒绝。没有确认的正式符号名或完整 C 类型。

- 验证来源、目标、主将、兵力、有效状态及世界部队表，禁止同一对象。
- 两方势力编号合法且不同，并通过 `0x299BC0` 的势力关系检查；其完整外交语义未命名。
- 当前格子合法并由对应部队占据。
- `0x280570(来源格,目标格)` 得到方向 `1..6`，再用 `0x279EB0(来源格,方向)` 核对确实相邻。
- 目的格为 `0x279EB0(目标格,相同方向)`，即沿来源到目标方向继续走一格。不是撤退命令，也没有连续推动占位部队。
- 合法棋格编号为 `0..48399`；`48400 / 0xBD10` 为无格哨兵。使用六角相邻函数处理边界，不能直接给格号加减。
- 目的格的部队占位 `+0x1C`、另一类占位 `+0x1A` 必须为空，并通过 `0x296420(目的格,1,目标部队,0)` 地形 / 通行检查，才能设为位移模式 `0`。
- 越界、合法对象阻挡或通行检查拒绝，形成受阻模式 `1`；损坏的对象、身份或数据则拒绝整个计划。
- 返回前复核世界、身份、主将、棋格、占位及目标相关兵种字段。

计划固定为 `40` 字节：

| 偏移 | 已核对内容 |
| --- | --- |
| `+0x00 / +0x08 / +0x10` | 来源部队、目标部队、世界指针，各 8 字节 |
| `+0x18 / +0x1A` | 来源 / 目标部队编号，各 2 字节 |
| `+0x1C / +0x1E` | 来源 / 目标主将编号，各 2 字节 |
| `+0x20 / +0x22 / +0x24` | 来源 / 目标 / 目的棋格，各 2 字节 |
| `+0x26 / +0x27` | 方向 / 模式，各 1 字节 |

规划器自身没有检查来源兵种等于 5；这个限制在上层收集和批执行中。这为通用效果抽取提供了线索，但不代表可以脱离调用上下文直接安全使用。

## 执行、占位和路径

`0x248306B(plan)` 在执行前重新规划，再比较原计划与新计划。失效或不一致返回 `0`，符合后置检查返回 `1`，后置状态异常返回 `-1`。

位移模式调用链：

1. 保存目标部队 `+0x48` 原值，通过 `0x2BB4D0` 临时设置目的格。**`+0x48` 是移动目的字段，当前格是 `+0x2A`**。
2. `0x25A3E0(目标旧格)` → `0x2054D0` 清理旧格部队占位。
3. `0x257B2E0(目标部队,0)` 包装调用原有 `0x2A97A0`。包装层还同步其自身的部队位置记录，不能未经分析绕过。
4. `0x2A97A0` 设置新格占位（调用 `0x21D720`）、写部队当前格 `+0x2A`、更新方向并调用其他原有处理及通知。它还包含地形切换的分支和其他字段处理，不能概括为无副作用的独立标量设置器；各分支含义仍待核对。
5. `0x2482EFF` 复读目标身份、当前格、旧格已空及新格占位正确。
6. 成功后经 `0x2BB4D0` 把临时目的字段设为无格哨兵，再调用 `0x2CCD50(目标部队,0,1,0)` 路径处理，随后再次验证占位。后三个参数的完整业务含义未知。

第一次移动后校验失败时会调用 `0x2482F7B`：仅当目标仍在旧格且对象有效时，尝试补回旧格占位并恢复原 `+0x48`。这是**有条件的补救**，不是对任意已发生位移和原有事件副作用的完整事务回滚；不能向界面保证所有失败均自动无损恢复。

## 受阻后的混乱

`0x2482FE1(plan)` 读取目标部队 `+0x23`：

- 原计数已经大于 `7`：不缩短，返回成功。
- 原计数小于 `8` 且目标 `+0x0C` 标记非零：不写，返回无效果；标记业务名称未知。
- 否则调用 `0x202F40(目标部队,0,8-原计数)`，再复读身份、棋格、占位及计数；未达到 `8` 报故障。

项目既有异常状态研究已把模式 `0` 和部队 `+0x23` 识别为混乱。`0x202F40` 是加减计数并按全局上限钳制的底层设置器。因此这里是“尝试把混乱计数补到至少 8”，不是每次额外叠加 8，也不会把更长的已有混乱减到 8。**计数 8 对应的游戏日数尚未核实。**

此处直接调用 `0x202F40`，没有经过插件当前混乱拒绝所接入的 `0x2BBFB0`。后续设计抗混乱能力时必须专门核对兼容，不能假定现有插件钩子自动覆盖这个受阻分支。
