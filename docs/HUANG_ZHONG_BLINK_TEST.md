# 黄忠专属闪袭背刺测试版

版本：`0.11.0-dev.3`；2026-10-10。代码已接入、独立测试已覆盖，**真实游戏中的位移、显示、伤害与保存重启仍待验收**。这是本地测试快照，不代表基础六页武将编辑器已经完成。

## 安装与启用

保存存档并退出游戏，从游戏目录外运行本包安装器，设置目录为含 `SAN14PK_SC.exe` 的游戏目录，点击“安装 / 更新”。重新启动、载入存档后，按 **F10 → 测试功能 → 闪袭背刺 · 黄忠** 开启。默认关闭；展开条目可查看兼容状态。无需重建黄忠部队，已有部队也可测试。

只作用于原始武将编号 **271** 且原始姓名唯一为“黄忠”的**主将**部队，不赋予副将、其他武将或随机 AI 词条。编号与姓名来自当前游戏的只读核对，不修改原始姓名、个性槽或兵种定义。启用时部队名称增加“闪”前缀；测试范围为双方有效阵形编号 1–10 的陆上战斗部队，不包含水军和运输队。

## 实际规则

1. 黄忠对一个相邻敌对部队造成真实普通直击兵力损失后，记录一次闪袭意图。本次伤害本身没有背刺加成。
2. 等当前战斗结算返回并完成 EXE 原有长枪击退处理，再核对双方身份、创建序号、位置与会话。沿黄忠到敌军的接敌方向继续查找敌军后方第 **1、2、3 格**，选最近的空闲、原生落脚检查允许的格子。
3. 移动黄忠部队，敌军和途中部队不移动。三格均不合法或越过边界无落点时不闪袭、不消耗冷却。原有长枪先移动了敌军时取消这次意图。
4. 成功位移后，黄忠获得一次针对原目标的背刺机会：游戏本身允许的下一笔普通直击扣兵量 **+30%，向上取整**。只在实际造成兵力损失时消费，不能连续加成、不能触发额外强制攻击。战法、火伤、扩展攻击子通道和其他目标不获得加成。
5. 从成功闪袭当天起冷却 **5 个游戏日**，背刺机会也最多保留 5 日。目标移动、移除或部队身份变化会使机会失效；伤害结算时仍需敌对、且黄忠处在原接敌轴后方三格之一。

落在第 2、3 格时，不扩大普通攻击距离，等待原游戏允许的攻击。后方按**此次接敌轴**定义，尚未证明原生敌军朝向字段，不能理解为精确识别敌军面向。瞬移不执行完整沿途行军路线检查；跨山、墙、关隘的额外限制尚未加入。位移后复核当前格、旧格已空、新格占位和目标仍在原格；部分失败会停用能力并记录原因，不能保证所有原生副作用完整回滚。

## 保存与故障

冷却与背刺机会由正常游戏保存挂接到独立附属文件：`SAN14ModManager/blink-backstab/<存档SHA-256>.s14blink`。未执行意图不保存。重启恢复、旧档回退、部队编号复用分别处理；没有附属文件的旧档从空状态开始。附属文件损坏或写入失败时停用能力，不覆盖未知数据。关闭功能取消待执行意图和未消费机会，保留已消耗冷却；重新开启不会刷新冷却。

“移除插件”保留附属文件，“彻底卸载”仅清理能通过格式、校验和归属验证的本项目附属文件。没有修改游戏 EXE；本轮没有自动安装或发布 Release。

## 验收记录与实机步骤

独立合成游戏对象测试覆盖：六个方向，B1/B2/B3 最近合法落点，占位/地形/边界，黄忠资格与重名排除，无实际损失不触发，重复和嵌套攻击，过期身份和执行代次，原有击退先移动目标，方向适配调用范围，整数溢出，部分位移失败停用，开关与冷却，附属文件读写、跨进程恢复、旧档回退、损坏保留、编号复用。完整构建和回归结果见包内 `verification.json`。以上不等于真实游戏位移已通过。

建议另存测试档，按以下顺序验收并保留日志：

1. 开启后确认只有黄忠主将部队出现“闪”；其他部队和黄忠副将不触发。
2. 黄忠相邻普通攻击，观察 B1 落地、敌军不移动、旧格可正常占用，检查命令、路径与部队显示。
3. 占住 B1 验证 B2，占住 B1/B2 验证 B3，再验证全部占住时不移动；覆盖六个方向与地图边界。
4. 验证下一笔对原目标的合法直击只加成一次；超出攻击距离时等待，目标移走后取消；战法和火伤不加成。
5. 验证 5 日冷却、关闭再开启、保存重启与旧档回退，检查原有探索、F 查询和战绩仍正常。
6. 检查 `SAN14ModManager/logs/` 的 `blink_ready`、`blink_officer_resolved`、`blink_landed`、`blink_backstab`；`blink_move_fault` / `blink_save_fault` / `blink_sidecar_fault` 应对应停用原因。
