# 武将军功账本

基本页最后一行显示“军功”，表示该武将当前可消费余额。

规则版本 1：敌军损失每 100 人记 1 点（与已有杀敌总数一致，含伤兵）；击溃敌方部队每支记 100 点；击伤敌方武将每次记 50 点。三类奖励相加。同军伤害、不明来源及重复战斗回调不入账。己方损失与覆灭不扣分。不足 100 人的损失余数跨战斗及读档保留。

每名武将独立保存 `earned`、`spent`、`enemy_remainder`。余额为累计获得减累计消耗，新战绩直接增加累计获得，不重算余额。原始五项战绩保持原值。

## 消费接口

`s14_merit_row(world,officer,&account)` 读取账户；`s14_merit_spend(world,officer,amount,expected_spent)` 在余额足够、世界/武将有效、没有读档且已消耗额与调用方读取的值一致时扣款。零额、超额、过期及重复提交均拒绝。调用方必须在统计工作线程执行，原生 UI 应经请求队列转交该线程。未来科技学习可使用此接口；本版科技树仍然为演示升级，没有实际学习扣费按钮。

## 保存与迁移

沿用游戏存档 SHA-256 对应的 `.s14career` 旁存文件，格式升级为 v2，同时保存战绩、军功账本和部队生命周期去重。成功保存游戏时写入；读旧存档恢复旧余额，另开战役清零。消费后也需要保存游戏才能跨进程保留。

旧 v1 文件仍可读取及识别。读取时按已有的有效累计战绩一次性计算初始获得额，消费额从 0 开始；后续保存写入 v2，重新读 v2 不重复补发。累计额使用饱和算术防止溢出。未知或损坏文件不覆盖。

测试覆盖：不足百人余数、消费后新战绩继续增加、余额不足和重复消费拒绝、友军排除、事件和部队生命周期去重、武将隔离、存档回滚、v1 迁移后保存 v2、跨进程恢复与溢出边界。原生页面测试检查军功标签及消费后余额显示。
