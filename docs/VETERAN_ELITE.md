# 百战精锐 · 曹仁（0.9.7 本地测试版）

本次只用于曹仁（武将编号 518）。F10 → Mod → “百战精锐 · 曹仁”，开启后按当前存档的生涯战绩判定。

| 项目 | 行为 |
| --- | --- |
| 条件 | 曹仁已记录斩敌总数达到 5000，含伤兵 |
| 武将姓名显示 | 神 曹仁 |
| 部队名称显示 | 神 曹仁 |
| 真实效果 | 曹仁担任主将的有效部队，原生实际攻军、防御乘 1.10 |
| 基础白字 | 沿用游戏原生计算 |
| 视觉 | 达标后显示原有同帧紫色光圈，悬浮显示“百战精锐”和攻防增幅 |
| 进度 | 展开 F10 的词条 Mod 查看；部队数值解析明细也显示进度 |
| 解锁时机 | 回合结束后统一判定，下回合使用；读取已达标存档时直接恢复 |
| 解锁提示 | 正常回合首次从未达标变为达标时，显示 2 秒提示 |

只有已记录战绩参与判定，不补算安装前或关闭战斗采集期间的战绩。已知记录存在缺口时显示说明，仍按真实已记录数量判定。此次不修改统计数字或降低门槛用于实机演示。

## 开关与旧版本迁移

“百战精锐 · 曹仁”接管原先“曹仁攻防增幅”开关，保留已有 `Features/CaoRenAttackDefense` 配置值。通用安装包默认关闭，更新保留现有选择。

从旧版更新后，曹仁未达到 5000 时不再无条件获得 +10%。达标后也只增加一次，不将旧固定加成和词条加成重复相乘。

地图光圈、悬浮说明仍有两个独立视觉子开关。关闭显示不取消真实效果；关闭词条父开关则停用加成、称号、光圈和说明。游戏原生文本通常在下一次原生界面刷新时恢复，因此关闭后重新悬浮或重新打开详情核对。

战斗采集开关控制后续记录；停止采集不会自动删除当前有效存档已取得的词条资格。管理器总开关关闭会停用效果。

## 名称与存档

姓名通过原生格式化入口输出前缀，队名通过部队名称入口输出完整别名。武将编号和原始姓名字段不变，不在游戏存档中永久写入“神 ”。F 武将一览、原生武将详情战绩条和部队数值解析使用同一个别名接口。搜索曹仁、拼音或首字母仍沿用已有搜索逻辑。

条件从与游戏存档绑定的生涯检查点派生，不另外保存一份解锁计数。普通/自动存档沿用既有绑定机制；读取达标前的旧档会恢复未达标，重新出征仍按同一武将的累计记录判定。

开始读档或新战役时立即让资格缓存失效。工作线程完成该次读档后恢复统计，再按读档序号发布资格；旧回合和旧读档队列不能在新载入期间重新启用词条。失败读档从保留的当前生涯记录恢复。

## 实现与验证边界

- `career_affix.c` 提供有界资格缓存、存档载入序号、姓名输出和进度，不在计算/绘制回调读取磁盘或扫描全武将。
- `battle_probe.c` 在载入完成及回合结束后从工作线程的生涯统计发布资格，正常战斗事件不立即改变增幅。
- `army_buff.c` 在原生计算结果上应用一次倍率；不开启或不达标时返回原值。
- `affix_names.c` 验证原生姓名/队名入口。姓名格式化使用同长度字段的局部副本，不往未知容量的输出缓冲区强行前插字符，不写实时武将结构。
- 原生计算仍只调用一次；姓名、数值和视觉共用同一资格，仍逐次校验有效世界、武将和规范部队。

独立验证包含门槛边界、实际事件桥、重复事件、旧档回退、跨进程恢复、失败读档、新战役、过期队列、姓名缓冲/原始字段保护、多线程姓名以及真实 MinHook ABI 的私有样本。私有反汇编入口检查不等于游戏内姓名和完整结算已经验收；安装后需核对原生悬浮名称、武将详情、真实攻防、开关和完整回合。

后续通用词条规则见 [战绩词条设计](CAREER_AFFIXES.md)；光环、减伤和恢复此次没有启用。
