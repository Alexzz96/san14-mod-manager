# 天下归心 · 三国志 14 功能管理器 0.7.3（预发布）

0.7.1 新增随存档保存的武将累计战绩，支持杀敌数（含伤兵）、击溃部队、自身覆灭、兵力损失及击伤次数排序。武将列表取消每秒刷新，仅在按 F 打开时采集一次。沿用 0.5.2 的武将视图改为与管理器一致的暖白和陶土色页面，增加中文 / 完整拼音 / 首字母搜索、野心 / 情义 / 忠诚显示及排序。沿用用户已确认有效的手动关闭方式与 0.4.3 探索结果弹窗：右上方“关闭”、标题栏 × 或 Esc 收起武将视图，切换焦点不自动关闭。武将一览实时查看城市、关隘、出征及执行任务中的武将，保留五维基础能力排序。此前本地版本的探索弹窗、武将搜索与战绩列表已由用户确认有效；非零战绩重启及旧档回退仍待完整实机验收。

本版保留回合自动搜索、三组探索设置、回合结果统计、同名旧版识别、彻底卸载及暖白界面。已包含全势力战斗采集、自势力回合报告和 F 战绩；新安装默认开启战斗记录与自动探索，执行武将选择“各官员以外”，更新保留用户选择。安装与状态页支持检查 GitHub 更新、下载并校验新版安装器；新安装默认关闭墙体 5 格限制，更新保留已有开关。详见 [在线更新](GITHUB_UPDATE.md)。

## 已有功能

| 项目 | 行为 |
| --- | --- |
| 扩展功能总开关 | 关闭所有追加功能，保留各项选择；F10 管理器仍可打开 |
| 墙体连片上限（默认关闭） | 当前棋格所属势力相同的土垒和石墙合并计数，整片最多 5 个 |
| 超限悬浮提示 | 点击超限位置时说明规则，5 秒后消失；依赖墙体连片上限 |
| 诊断日志 | 可选的详细检查/建造日志，默认关闭 |
| 回合自动搜索（默认开启） | 执行武将默认“各官员以外”；确认“进行”后按原生规则使用剩余政令，提示 2 秒 |
| 探索统计 | 回合后显示武将、名品、战法书、金钱与原生报告明细 |
| 武将一览 | 字母 F 打开；名称 / 个性搜索，五维排序，城市与出征数据统一显示 |

游戏内用 **F10** 打开或收起功能管理器，用字母 **F** 打开武将一览，无常驻按钮。也可点击右上角关闭或按 Esc 收起。外部 `SAN14ModManager.exe` 提供相同开关及安装维护。设置自动保存，两处共用 `SAN14BuildLimit.ini`。外部修改约 250 毫秒内由游戏读取，连接状态约每秒刷新。

已启动的检查可能使用切换前的设置；新设置从下一次检查起使用。关闭期间可以允许超限建设，再开启不会拆除已经出现的墙体。尚未开工的命令会在实际开工时按当时设置再次判断。

关闭总开关不卸载接入入口，只快速返回原游戏结果，因此可以在同一次启动里恢复功能。若出现数据解码异常，追加规则会保护性停用，本次启动不能重新启用；管理器显示原因，设置仍可保存，重启后重新校验。

## 安装方式

推荐发布包中的单个 `SAN14ModManager.exe`，插件已经嵌入 EXE，不需要 Python、编译器或手动复制 DLL。

1. 保存存档并完全退出游戏，关闭游戏目录中的旧管理器。
2. 将发布包解压到游戏目录外，双击新版管理器，进入“安装与状态”，选择含 `SAN14PK_SC.exe` 的目录。
3. 点击“安装 / 更新”，确认出现“安装完成”弹窗及“已识别本项目插件”状态。启动并载入存档后，F 查看武将，F10 查看管理器。

安装器只确认目录中有 `SAN14PK_SC.exe`，不检查游戏版本号或 EXE 的 SHA-256。检测到其他或来源未知的 `dinput8.dll` 时拒绝覆盖。没有安装记录时，也能通过已核对哈希识别本项目 0.2.0、0.2.1、0.2.2 发布文件及早期已确认插件；当前包的 DLL 和手动复制的管理器也可识别。正在运行的同一管理器文件不会重复替换。更新前备份旧插件和管理器，暂存文件通过哈希检查后再替换；替换管理器失败时回退插件。文件占用、权限或回退失败会显示具体错误，不强制结束游戏。

## 移除与彻底卸载

两种操作都要求完全退出游戏。

| 操作 | 清理范围 |
| --- | --- |
| 移除插件 | 只删除已识别的 `dinput8.dll`；保留管理器、设置、日志、记录及备份，方便重装 |
| 彻底卸载 | 删除已识别的 DLL、游戏目录中的管理器、配置、安装及运行记录、本项目日志、有效战绩检查点、已识别备份与暂存文件，并删除空的管理器目录 |

彻底卸载会先显示确认提示。**请从游戏目录外的安装包运行，并关闭游戏目录中的管理器。** 若当前程序就在游戏目录中，会明确提示无法删除自身，且不会先删一部分文件。

没有安装记录的同名本项目发布文件、单独复制的当前管理器、仅剩安装记录或有效配置，都可以检测和清理。未经识别的同名程序、被修改且无法确认的 DLL、其他文件和子目录保留，结果会说明保留情况；仅同名不代表属于本项目。备份也核对归属，不删除其他 MOD 的备份。游戏 EXE、资源与存档不在清理范围。

清理只访问固定的管理器路径，不递归删除整个目录。删除前检查全部待清理文件的路径和占用；链接目录不跟随，硬链接、只读或占用文件会阻止清理。结果显示实际清理的文件和空目录数量，权限错误会说明未完成。

命令行支持 `SAN14ModManager.exe --install "游戏目录"`、`--remove "游戏目录"` 与 `--uninstall "游戏目录"`；最后一项直接执行完整卸载，请仅用于已经明确选择的目录。

启动时核对实际建造接入点、调用位置和内存是否可读，再安装钩子。入口对不上时显示“建造接入点未匹配”，只停用扩展功能，F10 管理器仍可使用。此检查用于避免修改错误代码，不对游戏版本或整份 EXE 设置白名单；它也不代表所有版本都已实机验证。

插件和管理器自身的完整性检查、备份与未知代理文件保护仍保留。

| 安装后的文件 | 用途 |
| --- | --- |
| `dinput8.dll` | 游戏启动接入 |
| `SAN14ModManager.exe` | 独立管理器及嵌入式安装器 |
| `SAN14BuildLimit.ini` | 功能选择，更新时保留 |
| `SAN14ModManager/installation.ini` | 所安装文件的哈希与版本 |
| `SAN14ModManager/runtime.ini` | 连接心跳与生效状态 |
| `SAN14ModManager/search-results.ini` | 最近一次搜索统计及中文明细；彻底卸载会清理 |
| `SAN14ModManager/backups/` | 上一个插件、管理器版本 |
| `SAN14ModManager/logs/` | 启动与诊断记录，每次启动日志上限 16 MiB |

无边框模式下的悬浮提示已实机确认。管理器首版按同一窗口模式接入；独占全屏的管理器可见性尚未验收。

## 后续拓展

可继续加入其他建造规则、地图范围提示、施工提醒、可调参数、多套配置方案、配置导入导出和更新管理。“更多拓展”提供武将一览和战斗数据记录开关；武将累计战绩与原生存档绑定，更多事件仍需核实。

本版提供集中功能登记表及依赖判断。新功能的稳定 ID、配置键、名称、说明、分类、开关位、依赖及生效方式登记在 `features.c`。界面自动列出登记项，超过三项可滚轮浏览。新增实现需读取统一的生效开关，并核对新的接入点、代码字节和内存范围；登记项目本身不会自动实现游戏效果。当前位图支持至多 31 个独立开关，更多功能需扩展配置表示。

功能代码通过新版本管理器发布，安装前退出游戏；本版没有任意 DLL 的动态加载。可以先维持统一模块构建，功能增多后再分离版本适配层、规则模块、提示模块与参数编辑器。

## 现场验收

1. 点击安装后应出现结果弹窗，界面显示“已识别本项目插件”；启动后按 F10，确认连接状态。
2. 保持墙体上限开启，点击第六格，确认提示及拒绝下令。
3. 关闭“超限悬浮提示”，再次点击同格：命令仍拒绝，但不再弹窗。
4. 恢复提示，再关闭墙体上限：同格恢复原游戏判断。先取消测试命令，避免实际生成第六座。
5. 同次启动重新开启上限，第六格再次拒绝；总开关关闭后再开启亦应恢复。
6. 重启游戏，确认设置保留；在合法位置建造并正常结算。

独立测试已覆盖配置往返、未知键保留、依赖、总开关恢复、实际规则入口的私有地图关闭/开启结果、安装更新移除、未知 DLL、中文路径、文件占用回退，以及原有规则和代理转发。F10、界面点击与新版本结算仍需实机验收。

第三方依赖：MinHook v1.3.4（BSD）和 pypinyin 0.55.0 派生拼音词表（MIT），完整许可随包附带。玩家无需安装 Python，也无需联网进行搜索。快捷键与目录选择采用 Windows 原生接口，参考 [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) 与 [Common Item Dialog](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)。

## 武将一览

载入存档后，点击游戏地图窗口并按字母 **F**。在顶部搜索姓名、字或个性名称，可输入中文、完整拼音或拼音首字母，例如“曹操 / caocao / cc”“张嶷 / zhangni / zy”“山战 / shanzhan / sz”。大小写不敏感，空格分隔表示同时匹配，例如“zy sz”。吕布也支持 lvbu / lubu / lb。可筛选全部势力 / 自势力，以及城市关隘、出征部队和执行任务；默认显示现存武将，包括在野、俘虏与未发现状态，“全部记录 / 历史”另包含未登场、死亡等记录。

界面与管理器采用相同的暖白、陶土色页面风格。列表与详情新增野心、情义、忠诚：野心 / 情义显示 1～5 级，忠诚保留实际数值，无所属或不适用项显示“—”。点击五维、总和、兵力、三项内心信息等表头排序，再点切换升降序；顶部也能选择排序项目。五维使用基础能力，尚未计入官职、名品与伤病修正。选中武将查看字、归属、位置、健康字段、全部个性说明和战法名称，详情可滚动及复制。

按 F 打开时只读采集一次，保持窗口打开期间不再读取游戏数据；搜索、筛选、排序及查看详情使用这次快照。需要新数据时先关闭，再回到地图按 F 打开。读取失败时保留上次列表并提示重新打开，不自动重试；不会主动暂停回合。切换应用、搜索及下拉框不再自动关闭；窗口使用普通层级，不长期置顶覆盖其他应用。点击右上方“关闭”、标题栏 × 或按 Esc 收起，从游戏主窗口再按 F 也能收起。F 只在游戏主窗口聚焦时生效，输入框里的 F 是正常字符。F10“更多拓展”可启停此入口，也可在外部管理器修改；显式关闭开关或 F10 切换管理器时收起，只读视图独立于规则总开关。

F 已接入杀敌数（含伤兵）、击溃部队、自身部队覆灭、自身兵力损失和击伤武将，均可排序。开启战斗记录后从采集起点累计，保存游戏建立独立战绩检查点，成功读档时恢复对应计数；实际阵亡和击杀武将仍显示未采集。备份或迁移需连同 `SAN14ModManager/career` 目录，彻底卸载会清理有效检查点。新增存档接入仍待实机验收，详见 [存档战绩](BATTLE_CAREER.md)。已对当前存档只读核对 1,400 条记录、599 位现存武将，模型、窗口及未知计数测试通过，安装后仍需验证 F、搜索、排序、Esc 和正常回合刷新。

F 无反应时，可查看启动日志的 `officer_input`：面板创建、启用状态、热键注册和错误码；`officer_toggle` 记录实际收到 F 及读取结果。开发接口与数据边界见源码中的 `docs/OFFICER_VIEW.md`。

## 自动搜索设置与验证

按 F10 进入“自动搜索”页，启用开关并选择以下设置。总开关必须开启。安装包默认不主动开启新增自动化，现场安装可根据用户要求启用；更新保留已有设置。

| 设置 | 可选项 |
| --- | --- |
| 执行武将 | 全武将 / 各官员以外 / 县府官员以外 / 城市官员以外 |
| 返回天数 | 10 天以内 / 20 天以内 / 无限制 |
| 重视项目 | 优先军师推荐 / 优先能力 |

确认“进行”之后才派遣，取消确认不会消耗政令。优先保留已经下达的任务，使用剩余政令；无空闲武将、无城市或政令不足时在管理器显示原因。原生探索功能、费用、成功率与时间计算保持游戏的规则。派遣后显示“开始自动搜索”悬浮提示 2 秒，提示不拦截鼠标、不暂停结算。

结果统计包含本势力自动与手动探索。回到下一次地图规划界面时显示完整结果弹窗，例如“张辽 → 襄阳郡：找到金钱 321”或“曹操 → 汉中郡：探索失败（未发现任何收获）”。每次已完成的探索都列出，原生日志的颜色控制码不显示；发现武将的登用成败以该条原生明细为准。结果弹窗不自动倒计时，点击弹窗任意位置关闭；条目超过窗口高度时，用鼠标滚轮查看。切换到其他应用时暂时隐藏，切回游戏恢复。开始提示仍显示 2 秒，墙体超限提示仍显示 5 秒。

按 F10 可查看统计及最近报告预览，完整明细也保存在 `SAN14ModManager/search-results.ini`。较长任务在实际结束的回合计入，正在返回不会重复统计；在途数量包含正在探索与返回的任务。任务由游戏保存，插件不另建任务系统。重载较早存档或切换势力时会重置本次统计缓存。

建议先用测试存档完成以下验收：

1. 确认 F10“自动搜索”已开启，保留若干政令，先点“进行”再取消，核对政令与任务未变化。
2. 再次确认进行，检查是否出现约 2 秒提示、探索任务与政令扣减，回合结算是否正常。
3. 回合后对照原生探索报告和弹窗明细，确认执行武将、地点、发现类型、名称及金额对应；失败条目也应列出，滚轮能查看末尾，点击关闭后不再恢复。
4. 切换三组条件，核对被派遣的武将和原生自动搜索的筛选结果。
5. 选择长途探索，保存重启并继续回合，确认实际发现时才计数；关闭本开关后确认没有新的自动派遣。

启动日志中的 `search_ready` 表示探索代码入口是否接入。`event=auto_search` 记录派遣、原生结果、回合汇总与异常，关闭墙体诊断日志也会保留这些摘要。探索入口不符合实际指令或数据异常时只停用自动搜索并在本页显示原因；原生探索菜单仍可操作。

安装失败会显示包含原因的弹窗，底部错误文字也会突出显示。F10 无反应时可查看日志中的 `manager_input`：游戏窗口是否找到、面板是否创建、游戏是否在前台、快捷键是否注册及错误码；`manager_toggle` 记录实际收到 F10 后的面板显隐。

## 战斗数据记录

F10 → 更多拓展 → 战斗数据记录。新安装默认开启，记录所有势力的技能及兵力原始事件；该开关是 F 清单与原生详情条累计战绩的来源，关闭期间不新增计数。正常状态为 HooksReady=1、Fault=0、Dropped=0；详情见游戏目录 `SAN14ModManager/battle-observation-status.ini`。单次进程战斗日志上限 256 MiB，发生溢出或文件错误会停止采集，不改变游戏原本的事件。兵力减少、击溃、自身覆灭及击伤次数接入 F 累计页；伤兵生成与实际阵亡不能混为一谈。已生成事件保存在 logs 的 battle-*.jsonl；具体范围、离线梳理命令及验证顺序见 [战斗数据说明](BATTLE_OBSERVATION.md)。
