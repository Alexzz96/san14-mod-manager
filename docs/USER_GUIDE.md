# 天下归心 · 三国志 14 功能管理器 0.3.0

本版包含独立管理器和安装器，增加同名旧版与残留检测、彻底卸载，并统一为 Claude 风格的暖白背景、深色文字、陶土色按钮与衬线标题。墙体限制、5 秒提示及 0.2.1 的 F10 打开已实机确认；本版已通过独立测试，更新后的游戏内显示、热切换及结算仍待实机验收。本版按预发布版本提供。

## 已有功能

| 项目 | 行为 |
| --- | --- |
| 扩展功能总开关 | 关闭所有追加功能，保留各项选择；F10 管理器仍可打开 |
| 墙体连片上限 | 当前棋格所属势力相同的土垒和石墙合并计数，整片最多 5 个 |
| 超限悬浮提示 | 点击超限位置时说明规则，5 秒后消失；依赖墙体连片上限 |
| 诊断日志 | 可选的详细检查/建造日志，默认关闭 |

游戏内只用 **F10** 打开或收起，无常驻按钮。也可点击右上角关闭或按 Esc 收起。外部 `SAN14ModManager.exe` 提供相同开关及安装维护。设置自动保存，两处共用 `SAN14BuildLimit.ini`。外部修改约 250 毫秒内由游戏读取，连接状态约每秒刷新。

已启动的检查可能使用切换前的设置；新设置从下一次检查起使用。关闭期间可以允许超限建设，再开启不会拆除已经出现的墙体。尚未开工的命令会在实际开工时按当时设置再次判断。

关闭总开关不卸载接入入口，只快速返回原游戏结果，因此可以在同一次启动里恢复功能。若出现数据解码异常，追加规则会保护性停用，本次启动不能重新启用；管理器显示原因，设置仍可保存，重启后重新校验。

## 安装方式

推荐发布包中的单个 `SAN14ModManager.exe`，插件已经嵌入 EXE，不需要 Python、编译器或手动复制 DLL。

1. 保存存档并完全退出游戏，关闭游戏目录中的旧管理器。
2. 将发布包解压到游戏目录外，双击新版管理器，进入“安装与状态”，选择含 `SAN14PK_SC.exe` 的目录。
3. 点击“安装 / 更新”，确认出现“安装完成”弹窗及“已识别本项目插件”状态。启动游戏后按 F10。

安装器只确认目录中有 `SAN14PK_SC.exe`，不检查游戏版本号或 EXE 的 SHA-256。检测到其他或来源未知的 `dinput8.dll` 时拒绝覆盖。没有安装记录时，也能通过已核对哈希识别本项目 0.2.0、0.2.1、0.2.2 发布文件及早期已确认插件；当前包的 DLL 和手动复制的管理器也可识别。正在运行的同一管理器文件不会重复替换。更新前备份旧插件和管理器，暂存文件通过哈希检查后再替换；替换管理器失败时回退插件。文件占用、权限或回退失败会显示具体错误，不强制结束游戏。

## 移除与彻底卸载

两种操作都要求完全退出游戏。

| 操作 | 清理范围 |
| --- | --- |
| 移除插件 | 只删除已识别的 `dinput8.dll`；保留管理器、设置、日志、记录及备份，方便重装 |
| 彻底卸载 | 删除已识别的 DLL、游戏目录中的管理器、配置、安装及运行记录、本项目日志、已识别备份与暂存文件，并删除空的管理器目录 |

彻底卸载会先显示确认提示。**请从游戏目录外的安装包运行，并关闭游戏目录中的管理器。** 若当前程序就在游戏目录中，会明确提示无法删除自身，且不会先删一部分文件。

没有安装记录的同名本项目发布文件、单独复制的当前管理器、仅剩安装记录或有效配置，都可以检测和清理。未经识别的同名程序、被修改且无法确认的 DLL、其他文件和子目录保留，结果会说明保留情况；仅同名不代表属于本项目。备份也核对归属，不删除其他 MOD 的备份。游戏 EXE、资源与存档不在清理范围。

清理只访问固定的管理器路径，不递归删除整个目录。删除前检查全部待清理文件的路径和占用；链接目录不跟随，硬链接、只读或占用文件会阻止清理。结果显示实际清理的文件和空目录数量，权限错误会说明未完成。

命令行支持 `SAN14ModManager.exe --install "游戏目录"`、`--remove "游戏目录"` 与 `--uninstall "游戏目录"`；最后一项直接执行完整卸载，请仅用于已经明确选择的目录。

启动时核对实际建造接入点、调用位置和内存是否可读，再安装钩子。入口对不上时显示“建造接入点未匹配”，只停用扩展功能，F10 管理器仍可使用。此检查用于避免修改错误代码，不对游戏版本或整份 EXE 设置白名单；它也不代表所有版本都已实机验证。

插件和管理器自身的完整性检查、备份与未知代理文件保护仍保留。

| 安装后的文件 | 用途 |
| --- | --- |
| `dinput8.dll` | 游戏启动接入 |
| `SAN14ModManager.exe` | 独立管理器及嵌入式安装器 |
| `SAN14BuildLimit.ini` | 功能选择，更新时保留 |
| `SAN14ModManager/installation.ini` | 所安装文件的哈希与版本 |
| `SAN14ModManager/runtime.ini` | 连接心跳与生效状态 |
| `SAN14ModManager/backups/` | 上一个插件、管理器版本 |
| `SAN14ModManager/logs/` | 启动与诊断记录，每次启动日志上限 16 MiB |

无边框模式下的悬浮提示已实机确认。管理器首版按同一窗口模式接入；独占全屏的管理器可见性尚未验收。

## 后续拓展

可继续加入其他建造规则、地图范围提示、施工提醒、可调参数、多套配置方案、配置导入导出和更新管理。界面“更多拓展”只列方向，未将这些计划显示为可用功能。

本版提供集中功能登记表及依赖判断。新功能的稳定 ID、配置键、名称、说明、分类、开关位、依赖及生效方式登记在 `features.c`。界面自动列出登记项，超过三项可滚轮浏览。新增实现需读取统一的生效开关，并核对新的接入点、代码字节和内存范围；登记项目本身不会自动实现游戏效果。当前位图支持至多 31 个独立开关，更多功能需扩展配置表示。

功能代码通过新版本管理器发布，安装前退出游戏；本版没有任意 DLL 的动态加载。可以先维持统一模块构建，功能增多后再分离版本适配层、规则模块、提示模块与参数编辑器。

## 现场验收

1. 点击安装后应出现结果弹窗，界面显示“已识别本项目插件”；启动后按 F10，确认连接状态。
2. 保持墙体上限开启，点击第六格，确认提示及拒绝下令。
3. 关闭“超限悬浮提示”，再次点击同格：命令仍拒绝，但不再弹窗。
4. 恢复提示，再关闭墙体上限：同格恢复原游戏判断。先取消测试命令，避免实际生成第六座。
5. 同次启动重新开启上限，第六格再次拒绝；总开关关闭后再开启亦应恢复。
6. 重启游戏，确认设置保留；在合法位置建造并正常结算。

独立测试已覆盖配置往返、未知键保留、依赖、总开关恢复、实际规则入口的私有地图关闭/开启结果、安装更新移除、未知 DLL、中文路径、文件占用回退，以及原有规则和代理转发。F10、界面点击与新版本结算仍需实机验收。

第三方依赖：MinHook v1.3.4，BSD 许可随包附带。快捷键与目录选择采用 Windows 原生接口，参考 [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) 与 [Common Item Dialog](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)。

安装失败会显示包含原因的弹窗，底部错误文字也会突出显示。F10 无反应时可查看日志中的 `manager_input`：游戏窗口是否找到、面板是否创建、游戏是否在前台、快捷键是否注册及错误码；`manager_toggle` 记录实际收到 F10 后的面板显隐。
