# 内政武将名单兼容问题排查（2026-10-13）

用户最新运行的快速设置窗口显示“武将名单对象不兼容”，黑白名单为空。

## 证据与判断

- 提示来自 `native/domestic_native.c` 的自势力名单补充读取。该代码扫描武将表第 1–6000 槽；在筛选身份和势力之前，要求每个非空指针对象的武将编号等于表索引。
- 游戏会为预留/自建武将槽分配类型正确、编号为 0 的未初始化对象。`native/officer_model.c` 已处理这一模式，原内政读取没有对应处理。
- 本次日志 `E:/314 mod/Romance_of_the_Three_Kingdoms_14/SAN14ModManager/logs/plugin-20261013-215420-68188.jsonl` 第 262 行记录 F 武将一览 `capture_ok=1`、`records=1400`。这支持读取规则差异的判断。
- 隔离样本在第 3001 槽加入此类空对象，第 5001 槽保留有效自势力武将，原内政读取复现失败；修改后成功，后续有效人物仍保留。

因此，已确认源码存在空槽兼容缺陷。不同剧本/存档可能改变预留槽分布并触发它；现有证据不能证明不同剧本采用不同的内政任命接口。旧日志没有记录失败槽位，当前未发现运行中的游戏进程，尚未对截图对应存档直接复核。

## 修复与验证

内政读取先校验可读性和武将对象类型，再采用与 F 武将一览一致的空记录判定：编号、姓名及字、军团/位置/身份、健康、个性、战法字段为空，五维为 0 或 1；允许非关键默认计数字段非零。确认空记录后继续扫描。真实人物编号不匹配、错误类型、带姓名/个性/身份的编号 0 记录仍拒绝。已有任职官员仍严格校验，不因空记录规则被略过。

错误提示增加失败槽位，以及编号不匹配时的实际编号，方便下一次实机定位。

独立编译并运行 `test_domestic_capture`、`test_domestic_model`、`test_domestic_bridge`，全部通过。新增回归覆盖空槽、五维为 1 的预留模板、后续有效人物、编号错位、错误类型、非空身份/个性以及任职官员指向空记录；纯规划测试另含 600 组穷举匹配与 300 组原生增量样本。

后续截图确认 Ctrl+G 右侧仅显示读取失败前的七名候选武将，底部仍为“武将名单对象不兼容”。这是失败快照中的部分人员，不能据此认定全表采集已经成功；府规划在全表读取失败后不会生成。

dev.20 同时将自动提示改为进入存档后后台读取完整快照，成功后检查有效 Preferences；未设置才自动打开。旧已显示标记不等于已保存设置。自动打开直接使用完成快照，避免先显示空窗口。日志增加城市、府、武将数量和失败原因。

隔离测试不等于该存档实机验收，安装结果另记录于本地安装证据。

## 后续同类审查（dev.21）

发现城市、府、个性全表扫描也将未使用的空指针判为整体不兼容。现改为读取完整指针目录后跳过未使用空槽；府引用缺失城市、武将/驻城人员引用缺失个性及错误类型仍拒绝，个性基础目录仍作为初始化校验。候选、驻留人员同时核对武将表中的对应指针，避免只凭类型和编号对异常对象调用原生函数。

个性目录读取提前到候选能力计算之前；每名人物先确认引用存在，再调用原生有效能力或个性效果函数。测试记录有效能力调用次数，确认首名候选引用缺失个性时不会继续调用原生能力适配器。

失败的手动预览不再发布部分人员/城市，保留诊断原因。后台自动解析仍在失败时重试；手动快速设置失败后须重新打开读取，搜索不会覆盖错误原因。

新增回归验证稀疏未使用目录、引用缺失目录、错误类型、编号6000、循环链表、领地格缺失和失败快照清空。静态复核原生开发/治安函数分别在 `0x240f46` 和 `0x244acf` 附近将最终值限制为至少1，原检查成立。固定城市/府/武将容量、数值上界及预测组合容量仍保留；没有将这些未验证限制声明为所有修改版均兼容。
