# 部队属性的计算位置与对照方法

游戏没有提供源码，下面是本机 EXE 的逆汇编定位与插件的观察代码。RVA 用于当前计算入口定位，不代表所有版本通用地址。

## 计算调用链

曹仁原生“部队详情 → 基本”页的更新入口为 `0x8062d0`，对应 `CInfoDetailArmyUnitDefault` 的第 48 个虚函数槽。另一个 `0x806ec0` 属于“能力”页，不能和基本页的对象类型混用。

基本页自然更新时调用：

| 入口 | RVA | 含义 |
| --- | --- | --- |
| 基准属性包 | `0x2ffb70` | 输出未应用实际修正分支的五项整数基准 |
| 实际属性包 | `0x2ffa60` | 输出应用实际修正分支的五项整数结果 |
| 基础状态计算 | `0x27b180` | 两种分支的基础计算值；含统率、兵力、士气等输入，尚未把各项系数逐一命名 |
| 个性效果汇总 | `0x243e70` | 119 类整数效果；包含满足条件的自身及传播效果 |
| 附加状态修正 | `0x2788c0` | 属性汇总前参与叠加的另一整数修正 |
| 攻军 | `0x283ad0` | 独立浮点结果 |
| 攻城 | `0x283d10` | 独立浮点结果 |
| 破城 | `0x27c220` | 独立浮点结果 |
| 机动 | `0x281e50` | 独立浮点结果，另有条件效果项 |
| 防御 | `0x27bd90` | 独立浮点结果；某些交战目标分支另有加法项 |

五项属性包的数组顺序是 **攻军、攻城、破城、机动、防御**。最终浮点转整数采用截断，后续显示增减来自实际整数与基准整数的差。

雷达图显示 `1114 + 1533` 的含义是基准 1114、最终 2647；`531 + 1360` 表示基准 531、最终 1891。这两例来自用户此前截图，不代表重启或推进后的当前数值。0.9.1 已取得另一场景的原生动态计算输出。

## 0.9.2 的细分入口

| 来源 | RVA | 观察内容 |
| --- | --- | --- |
| 主将有效统率 | `0x20ce20` | 基础计算内部，属性索引 0、标志 0xfff 的原生返回 |
| 兵种政策倍率 | `0x3ca600` | 阵形适用政策的百分制返回，两分支、五属性分别记录 |
| 政策强度 | `0x3ca6c0` | 倍率内部使用的政策编号及原生返回强度 |
| 府/领地 | `0x282230` | 实际分支返回浮点倍率及输出累计单位；该入口另有难度处理 |
| 连携数量 | `0x2815d0` | 满足原生条件的友军数量；结合原生配置换算每支增幅 |

阵形 getter 依次为 `0x283ff0`、`0x283f60`、`0x284080`、`0x281dd0`、`0x27bd00`。若存在 32 字节保护向量，按 vtable 中已验证的 `0xbfa0` 字节解码过程和规范阵形编号还原；其他解码器不猜测。默认字段分别为 `+0x83`、`+0x84`、`+0x85`、`+0x7f`、`+0x86`。

统率兵力基础项按当前原生参数还原：

```text
L = 原生有效统率
supported = min(兵力, trunc((floor(4L/3)) ^ 原生指数))
基础项 = float(sqrt(4*supported) / 原生除数)
       + float(L * 原生线性系数)
       + float(原生常数)
```

这不是最后白字。原生还会乘入士气、全局、地形等项，观察器保留这一处理后的原生公共计算值。0.9.2 只在可复核分支中检验最终白字，不用假设填平未分解差额。

攻军/攻城/防御基本页无战斗目标时：

```text
v = float(阵形系数 * 百分制政策返回) / 100
v *= 原生白字公共计算值
v *= 原生属性全局系数 / 100
v *= 白字分支的个性状态倍率
防御额外 v += 1
白字 = truncate(v)
```

当前观察代码 `native/army_observer.c` 只调用自然触发的原函数一次；`native/army_model.c` 解码阵形、解释来源、还原公式并检查闭合；`native/army_ui.c` 显示白字/蓝字与滚动明细。

生效个性来源取部队的 36 个效果编号与主将 9 个个性编号、原生生效位。资格未重算分支按原生条件解释，逐项汇总必须等于五项原生缓冲区才接受；未闭合时不会给单个个性标记虚假的贡献。

## 已解析的修正层

以下是可读的简化结构，省略了原生资格、地形和目标条件分支，不能当成完整游戏公式：

```c
// category: 攻军 5、攻城 6、破城 8、机动 4、防御 7。
units = active_effects[category]
      + active_effects[19]        // 全能力
      + native_additional_state;
// 机动在特定标志下还叠加 active_effects[116]。
units = clamp(units, -attribute_limit, attribute_limit);
effect_multiplier = 1 + units * percentage_step / 100.0f;
temporary_multiplier = 1 + signed_temporary_units * percentage_step / 100.0f;

// 各属性存在独立的阵形、全局及其他修正项。
// 攻军/攻城等已见到多个乘法层；防御还有目标条件下的加法项。
final_float = native_attribute_formula(native_base_calculation,
                                      formation_and_other_terms,
                                      effect_multiplier,
                                      temporary_multiplier,
                                      conditional_additive_terms);
final_display = truncate(final_float);
```

当前读取到的比例步长为 5%。攻军、攻城的个性/状态层上限为 ±12 单位，破城、机动、防御为 ±10 单位。它们分别是这一层的 ±60% 和 ±50%，不能理解为游戏全部效果的统一上限。

临时字段分别为攻军 `+0x4b`、攻城 `+0x4c`、破城 `+0x4e`、机动 `+0x4a`、防御 `+0x4d`，带符号。此前只读快照中曹仁防御临时单位为 10，其余四项为 0；按原生步长换算为防御临时修正 +50%。这尚未对应到某次具体战法的施放者，不能仅凭“铁壁”同名推断来源。

## 曹仁样本中需要区分的个性

从当前整合包字典读到：

- 骑将：使用重骑时全能力 +10%，效果类别 19、单位 2。
- 铁壁：每次被攻击格挡 120 点伤害，另有建筑工事相关效果。它不是单纯的“防御 +10%”个性。
- 沉着：相关异常免疫；直率：陷阱伤害修正；坚城：所属城市反击伤害修正。
- 另有无名称的附加个性表项，不按名称猜测作用或激活条件。

持有个性不等于当前触发。0.9.2 会尝试把生效列表与原生汇总闭合，未闭合及资格重算分支继续保留来源未解析说明，避免直接把所有说明里的增幅相加。

## 插件源码位置

- `native/army_observer.c`：`page_hook` 限定曹仁基本页；`packet` 捕获两组结果；`factor_hook`、`aggregate_hook`、`extra_hook` 捕获原生返回与中间汇总。
- `native/army_model.c`：`s14_army_capture` 只读核对选中部队；`s14_army_trace_matches` 验证世界、部队、页面和预览模式；`s14_army_percent` 按原生步长、上限解释修正层。
- `native/army_ui.c`：悬浮条与明细的呈现。

现有代码是观察适配器，保留原函数调用和结果，不主动调用游戏计算，不加攻防。

## 手动操作怎样提供有效对照

现有曹仁队已经在地图上，可以直接作为第一组，不需要重新出征或发生战斗。新版安装后，载入同一存档并打开曹仁队基本页，让游戏自然计算一次，即可记录五项基准、最终值和目前支持的修正层。

后续手动出征也可以验证，但当前采集限定为主将曹仁的真实地图部队详情，尚不采集出征命令里的临时预览对象。确认出征后打开该队详情即可；记录兵力、伤兵、士气、阵形和所在地。

优先每次只改变一个条件：兵力变化、陆上/水上预览、阵形或所在地；可变化后返回并重新打开详情获取新计算。通过同一主将的两组记录对照，再处理战法临时效果、附近友军和战斗损失。这样不会把出征、士气变化、伤兵吸收和友军连携同时混在一起。
