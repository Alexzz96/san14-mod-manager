# 0.7.0 武将存档战绩

F 武将一览增加五项累计列，点击表头或顶部下拉框可升降序排序。全部势力都会记账，搜索、拼音、首字母及自势力筛选照常使用。每次打开 F 采集一次页面快照，不每秒刷新。

| 字段 | 口径 |
| --- | --- |
| 杀敌数（含伤兵） | 已支持的原生伤害回调中，造成敌方部队健康兵力减少的数量；包含转为伤兵者，不等于实际阵亡 |
| 击溃部队 | 原生战斗覆灭原因、兵力为零且敌我来源明确时，记给攻击部队主将；同一部队生命周期去重 |
| 自身部队覆灭 | 本人任主将的部队因战斗覆灭次数；攻击来源不明仍可记录自身覆灭 |
| 自身兵力损失 | 本人任主将的部队在已支持伤害事件中减少的健康兵力，包括来源不明的火伤 |
| 击伤武将 | 原生负伤事件中由本人明确造成敌方伤势加重的次数，不是独立武将人数 |

不把队伍数字重复分给副将；不能明确归属的延迟火伤不计入某人的杀敌数。正常入城、撤退等移除不计为覆灭。伤兵吸收不是造成伤兵，实际阵亡、击杀武将及招募统计仍未接入。全地图采集覆盖当前已接入的事件种类，不能保证所有特殊机制均有记录。

## 保存和载入

保存成功后，读取刚保存的原生文件并计算 SHA-256，在游戏目录 `SAN14ModManager/career/checkpoints/<摘要>.s14career` 原子写入独立检查点；不修改原生 `.s14` 存档。检查点包含武将编号计数、开始日期、战役及分支标识和部队去重状态，并带格式、大小和 CRC 校验。

成功载入存档后，根据内容摘要恢复相应检查点。读取旧档会恢复旧计数，重新游玩继续从旧计数累计，不能混入被回退分支的未来事件。重启、改存档槽或复制同一存档内容时，摘要仍对应同一个检查点；相同游戏内容不用于合并不同游玩分支。新剧本从 0 开始。载入失败不清空当前计数。

更新前旧存档没有检查点，第一次载入会从 0 开始；不能补出历史战绩。没有匹配检查点或校验失败也从新的采集起点开始，损坏或未知文件保留。已采集的 0 与“未采集”分别显示。关闭采集或发生队列／文件错误时标注“有采集缺口”，之后数字仅为已记录部分。

当前物理存档定位适配本测试安装的 `Profile/<账号>/Saves` 和原生 `svdexSC` / `autosdexSC` 等文件名。多个账号存在同名文件而不能唯一确定时不绑定；其他存档位置尚未适配。保存／读取接口的独立测试已通过，真实手动保存、自动保存和重启读档仍需实机核对。

备份或迁移时一起复制游戏存档和 `SAN14ModManager/career` 目录。只复制原生存档不会携带这些新增统计。移除插件保留检查点；彻底卸载会删除通过校验的本项目检查点及空目录，未知或损坏文件保留。需要保留战绩时请先备份。

## 实机验收

1. 载入地图，确认状态 HooksReady=1、Fault=0、Dropped=0、ReadErrors=0；F 出现新增计数列并能排序。
2. 保存一个战斗前基准档，核对原生保存成功事件、文件摘要与独立检查点。
3. 完成一次可核对的交战，查看双方主将的杀敌、损失、击溃与覆灭；正常入城不增加覆灭。
4. 保存战后档，退出、重启并载入同一档，核对数字保留。
5. 读取战斗前基准档，确认恢复战前计数；重新交战只在当前分支累计。
6. 核对自动保存档也生成对应检查点。未完成以上步骤前，不将独立测试结果标记为实机通过。

## 开发接口

`battle_stats.h` 提供版本 1 的 `S14BattleStatsProvider`，按当前世界和武将编号读取统计快照。`s14_officers_attach_battle` 验证世界身份后映射到 F 模型；每个计数保留独立有效位；0.8.2 F 列表将未记录项显示为 0，按显示的数值排序，不修改后台有效位。后续可扩展字段及详情，不要求重新读取武将表来推测战斗历史。

`battle_save.inc` 仅旁观原生保存收尾、完整载入、载入读取器和剧本初始化；保留参数、完整返回值和 LastError。载入期间抑制战斗采集，成功后才切换统计。游戏战斗线程使用固定事件队列，后台按事件顺序累计和写检查点；保存／载入收尾读取物理存档摘要，不调用额外的游戏函数。

独立测试覆盖重启进程恢复、旧档回退、同日期分支、复制存档、事件与部队生命周期去重、未知来源、友军伤害、载入失败、新剧本隔离、损坏文件保护及卸载清理。私有测试文件、日志和游戏存档不进入源码包。

## 本地 0.8.3

F 战斗统计统一四字列名，增加杀损比值（斩敌总数 ÷ 士卒折损）；零分母和显示顺序见 [本地说明](RELEASE_NOTES_0.8.3_LOCAL.md)。既有五项累计与存档格式保持不变，未记录显示 0，斩杀敌将不从部队覆灭推算。

`battle_timeline.h` 提供按世界、武将身份查看的独立时间线快照，击溃／负伤在原有统计器接受并去重后写入，单挑／抓捕沿特殊事件接口写入。事件发生时只读棋格所属县府及其当前城市并保存当时名称，旧记录不猜测地点。独立 `.s14timeline` 版本 1 检查点使用存档摘要及 CRC，支持保存、成功读档、旧档回退、跨进程恢复和新剧本隔离；最多保留最近 16,384 条全局明细，不改变既有累计。旧特殊明细可导入，旧击溃累计不能恢复逐条历史。迁移必须复制整个 career 目录。
