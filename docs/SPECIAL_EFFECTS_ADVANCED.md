# 光环、减伤、免疫、伤兵恢复和士气保护

2026-10-09。延续特殊效果设计讨论；这是方案扩展，不是已实现功能，不修改当前游戏、配置、DLL 或已安装版本。以下名称和数值均为可调整样例。

## 1. 光环：把增益或减益传播给附近部队

这里的光环是范围能力。头像光圈只负责显示，不能代替能力是否实际生效的判断。

| 名称 | 目标 | 示例规则 |
| --- | --- | --- |
| 护军光环 | 两格内同势力部队 | 防御 +10%，可选择含不含来源自身 |
| 奋战光环 | 两格内同势力部队 | 攻军 +10% |
| 安军光环 | 两格内同势力部队 | 每旬额外恢复士气，数量可设 |
| 治军光环 | 两格内同势力部队 | 每旬按现存伤兵比例恢复可战士兵 |
| 威压光环 | 两格内敌对势力部队 | 攻军 -10%，敌对关系需要核对 |
| 坚定光环 | 两格内同势力部队 | 指定异常抵抗或战斗士气保护 |

范围按游戏六边形棋格的相邻层数计算，不按屏幕像素、方格或道路行军距离。第一版建议两格、同势力、同类取最强、不连锁传播。接收增益的部队不会自动变成新的光环来源。军团不同但势力相同可以受益；部队原始军团字节不能直接当势力编号。

同一光环多个来源只应用一次；不同类型分别计算，属性型结果纳入统一插件叠加上限。治疗等有结算动作的光环，对每个接收部队每旬只执行一次；多个来源使用同一结算前基数比较，取本次实际作用量最大的来源，平局使用稳定规则选择，避免遍历顺序影响结果。

来源失效、部队覆灭/入城、离开范围、归属改变或开关关闭后移除对应贡献。水陆、地形阻隔、是否包含来源自身、城内武将是否发光环，都应作为明确规则；首版仅限有效地图部队。显示可以给来源主光圈，给接收者小角标，悬浮列出“来自曹仁 · 护军光环 · 防御 +10%”。全地图范围环可另做，但需新的地图投影/地形显示定位，不等于已有头像光圈可直接画出来。

**现有基础**：`native/rule.c:s14_neighbors` 已用于六边形连接规则；部队格子、势力映射和攻防倍率已有基础。**缺少**：通用作用对象、范围资格、来源贡献、失效撤销、多部队绘制和动作去重。

## 2. 减伤：改变真正的士兵损失

| 名称 | 示例 |
| --- | --- |
| 坚甲护身 | 普攻造成的实际兵力损失减少 20% |
| 术法护体 | 指定战法伤害减少 20% |
| 御火护身 | 已辨认火伤减少 30% |
| 固定格挡 | 每次有效受击减少最多 50 人损失 |
| 临时护盾 | 获得总共 300 点可消耗的减伤额度，用完结束 |

防御提高 10% 与伤害减少 10% 是两种机制。直接减伤应该在已辨认伤害路径、原生减免算完之后、最终兵力和伤兵结算之前处理；最终提交位置还需要定位验证。不能对所有负向兵力变化统一减免，合并、调拨、断粮、撤退或事件变化不一定是敌方伤害。

固定减伤与比例减伤可以定义为 `插件后损失 = max(最低损失, floor(max(0, 原生损失 - 固定减免) × (1 - 比例)))`；这只是拟定规则。最低损失可以选 0 或 1，比例上限、同类取最强或相乘、固定额度与护盾的消费顺序必须明确。首版建议只做一类比例减伤，再加入固定格挡/护盾。

不能先让部队扣兵/覆灭再返还兵力，否则伤势、俘获、伤兵吸收与覆灭已经发生。已观察的原生铁壁效果也不应再次计为插件格挡。统计斩敌和自身损失仍记录实际发生量；只有明确的插件前后结算差才能计作“减免伤害”，防御光环不能靠估计认领减伤数字。

火烧涉及地图棋格和占用部队。单队火伤防护不能通过清除整格火实现，否则影响其他部队、格子和战法来源。

**现有基础**：`native/battle_probe.c:hooked_battle_troops` 观察来源、目标和前后兵力；`hooked_battle_wound_rate` 观察原生伤兵生成比例及中间扣减。**缺少**：各损失路径完整分类、正确的最终提交位置、减伤与伤兵/覆灭先后顺序及原生个性叠加验收。

## 3. 异常免疫、抵抗和解除分开设计

| 名称 | 示例 |
| --- | --- |
| 沉着免乱 | 阻止新增混乱，现有混乱不自动清除 |
| 行军不滞 | 阻止新增止步 |
| 镇定拒挑 | 阻止新增挑衅 |
| 异常抵抗 | 新异常的原生有效持续时间减少 50% |
| 临阵解控 | 每旬解除一次指定异常，或达到触发条件时解除一次 |

免疫保护新增/延长，抵抗缩短时长，解除处理已有异常。取得免疫时是否立即解控应为独立选项。正常倒计时、清除异常和原生命令收尾必须继续，不能每帧粗暴把计时字段写为零，也不能拦截全部状态 setter。

异常效果分别开关，初版不使用“全部异常免疫”掩盖未核实类别。现有观察器记录三个 mode 的计时变化，工具中 mode 1 标为止步，mode 0 混乱和 mode 2 挑衅仍有“待界面核对”标注；这些编号不能当作全部控制效果的完整对照。伪报、命令改变、火烧需各自核实，不能自动归入这三个编号。

原生个性已经免疫的场合不能另算插件拦截。显示和时间线可记录实际拦截的施放者、目标、异常类型和请求时长，但成功拦截应以最终提交与资格核对为准，不能按入口调用次数计数。

**现有基础**：`native/battle_probe.c:hooked_battle_abnormal` 观察施放来源、实际目标、mode、时长和前后计时。**缺少**：类别界面样本、最终资格/写入位置、所有来源路径以及既有异常/原生免疫与插件效果的交互验证。

## 4. 伤兵恢复：把现有伤兵转换为可战士兵

| 名称 | 示例规则 |
| --- | --- |
| 随军医护 | 每旬恢复现存伤兵的 10%，单次最多 200 人 |
| 战后救治 | 本旬未交战时，按更高比例恢复伤兵 |
| 得胜整军 | 成功击溃敌队后触发一次有上限的恢复 |
| 营地疗养 | 位于指定己方领地/营地时提高恢复比例 |
| 治军光环 | 为范围内同势力部队执行一次治疗结算 |

例：3000 可战士兵、800 伤兵，恢复 80 人后为 3080 可战士兵、720 伤兵，总人数保持 3800。这不复活已经消失的士兵，也不等于武将本人轻伤恢复。

每次恢复量受现存伤兵、比例/固定值、单次上限、可接收兵力余量限制。原生可接收兵力上限还需核实，不能默认与当前兵力或主将某个显示值相同。伤兵为零时不新增兵力。己方/友方范围按实际归属核对，原生吸收/补充伤兵先完成后，旬末治疗以最后剩余伤兵为基数。

建议第一版只在原生整旬结算完成后执行一次恢复，优先定位并使用原生恢复流程。读取详情、查询兵力、渲染头像都不能触发治疗。去重键至少包含战役分支、结算标识、出征身份、效果组；按存档检查点恢复已结算标识，防止读档或重复规划回调多治一次。

可战士兵增加与伤兵减少必须在正确原生流程中成对完成，不能只改一个计数。多个医护来源先选择/汇总规则再执行一次结算。以后可独立统计实际恢复人数和提供治疗的武将。

**现有基础**：前后可战兵和伤兵读取、旬末规划节点、伤兵吸收记录及存档检查点。**缺少**：原生恢复入口、容量规则、恢复/吸收/战后结算边界与一次性执行验证。伤害中的 `+0x18` 中间读数不能直接当作最终治疗基数。

## 5. 士气保护：明确哪些下降被阻止

| 模式 | 行为 |
| --- | --- |
| 战意不衰 | 所有已核实来源的负向士气变化无效，正向提升保留 |
| 临战不怯 | 仅阻止战斗/战法等指定来源造成的士气下降 |
| 军心稳固 | 士气下降不能越过设定下限；原有士气更低时不凭空提升 |
| 鼓舞军心 | 每旬恢复士气，与“不下降”分开 |
| 坚定光环 | 对邻近友方施加其中一种士气保护 |

“不掉落”建议默认解释为“不允许下降，但允许原生上涨”，不是将士气一直强制写成 130。也可以提供战斗保护、最低士气、临时保护一旬等独立规则。上限沿用原生规则。

完全保护与部分保护的来源范围必须明确，例如自然衰减、交战、战法、断粮、撤退、事件。上述分类是待核实的范围清单，不表示当前已经找到全部来源。取得效果时是否恢复至某值、解除效果后如何继续下降也需独立定义；建议默认只保护之后的变动，不追补此前损失。

需要修改减量判定/结算而不是改士气显示或用于计算的 getter。若只提高 getter，存档和其他系统仍可能读到下降后的真实士气。阻止士气下降也不自动取消断粮、撤退或其他原生效果。

**现有基础**：真实士气读数和其对部队基础属性的计算贡献。**缺少**：士气实际 setter/减量入口、来源区分、上限和所有下降路径验收。

## 统一显示、记录与推进顺序

每条效果共享状态：来源武将、目标出征身份、条件、范围、数值、期限、叠加分组、当前是否生效。头像主光圈只强调主要效果，其余用角标；右侧说明按来源逐条展示，避免多个整圈互相遮挡。颜色可按防护、医护、士气、减益区别，实际免疫/减伤触发时短暂强调。

实际效果开关与战斗记录开关应独立。关闭统计不应关闭已经生效的技能；战绩成长只暂停获得新的记录，已保存的资格按对应存档恢复。现有观察入口中部分读取仅在战法或战斗记录开启时执行，不能未经改造就作为所有来源的效果修改入口。

时间线可以记录“曹仁护军覆盖张辽”“曹仁格挡损失 50”“曹仁阻止一次止步”“医护恢复伤兵 80”“保护士气 5”。这里只记真实执行或明确拦截；持续光环不按渲染帧数计触发，属性型防护不捏造反事实伤害。

建议接入顺序：通用效果状态 → 防御光环 → 已辨认伤害路径的比例减伤/指定异常免疫 → 战斗士气保护 → 旬末伤兵恢复 → 完整士气保护、护盾和复合光环。每一项先单队/单来源，核对开关、来源归属和实际前后值，再验证多个来源、旧档恢复和完整旬结算。
