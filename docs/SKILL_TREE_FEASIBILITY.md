## 原生上限是否能改

上限是编译在 EXE 多个模块中的常量与数据结构约定，不是不可修改的硬件限制，也不是一个可调整的配置项。当前已确认的权限判断、按钮遍历、选中数据索引、图标映射均依赖既定编号。单独把 `20` 改大，不能让缺失的数据、图标、其他调用路径和存档处理自动存在。

原生权限字段是 32 位。这里的 32 位说明了现有权限结构，不能据此承诺已经支持 32 个兵种，更不能直接让第 21～31 个编号进入游戏。额外编号还需规范数据池、全体 getter、创建/销毁、战法适用、政策/个性、自动编制与存读档支持。超过该权限宽度又需要另一套权限存储。

兵种编号 getter 使用对象在规范池中的位置。另分配一个 `CFormationData` 副本并把它塞进按钮，也可能得到错误的编号。扩展原生池或接管数据寻址、权限、映射与保存是一项单独的引擎适配工作。**完全新增原生兵种编号理论上可以研究，目前没有完成验证，不能承诺修改几处上限即可稳定实现。**

## 推荐先实现插件兵种注册表

插件使用独立标识，如 `elite_xianzhen`，为每种兵种定义名称、图标、基础承载兵种、允许武将、解锁技能、属性修正、特殊效果和出征费用。这种注册表的设计数量不受原生 21 项约束；实际数量仍受界面、性能与已支持效果种类限制，不能称为无限。

例如“陷阵营”可以复用大戟的原生合法出征、地形和部队对象，在插件层作为独立选择：

1. 高顺尚未学习解锁技能时，不显示可选的陷阵营，或显示锁定说明。
2. 解锁后，在截图的兵种区域增加陷阵营按钮和独立图标；普通大戟、重骑继续保留。
3. 选择陷阵营才附上特殊兵种标识，预览其属性、特殊效果和费用。解锁不等于所有高顺部队自动转为陷阵营。
4. 确认出征时复核城内资金、兵力、武将和所选配置；成功提交后才绑定这一次出征身份并扣费。取消、重复点击和失败不得多扣或误绑定。
5. 部队详情与地图说明显示陷阵营，已支持的真实属性/效果按这支部队的标识计算。普通大戟和其他武将不受该配置影响。
6. 入城、覆灭、重新出征与读档按照各自身份恢复或移除标识，不以可复用的内存地址作为长期身份。

这是独立的插件兵种规则与显示，底层仍有原生承载类型。地形、政策和原生个性如何继承必须明确；独立三维兵模、全新攻击动画、原生 AI 自动使用新兵种不是现有接口已经支持的内容。新增按钮可以用插件绘制和交互，在原生兵种区域对齐；原生按钮列表、地图图标、原生情报列表等需要逐个接入，不能因一个按钮显示成功就视为全部同步。

高额金币建议区分“经验解锁费用”和“每次出征军费”。军费可设固定值、按兵力计价或两者相加。资金来自出征城市，预览、校验和实际扣费采用同一规则。原生最终扣费/提交入口尚未核实，因此这部分只能认定为可研究接入，不能宣称已经能准确扣款。不要在渲染或工作线程中直接扣金币。

## 高顺重骑机动 +10%

资格为：当前存档中高顺已学习相应技能，当前有效部队主将为 254，当前陆上兵种为重骑 2。执行一次原生机动计算后，对符合条件的有限结果乘 `1.10`；用原生结果作为基数，避免反复重算累乘。

机动入口的 ABI 与现有攻军/防御的浮点首参数入口不同，不能直接套用其函数指针。需要单独验证参数、真实部队与出征预览对象、陆上/水上分支和此整合包追加计算。预览也应自然经过同一技能规则，不能仅在地图真实部队里增加后导致出征面板仍显示旧值。

切换其他兵种、换主将、进入水上类型、关闭技能效果等条件不满足时，停止这项贡献。原生机动受地形、政策、个性和整合包分支影响，因此“机动 +10%”不保证整旬跨格数量恰好增加 10%。实机验收需用相同存档、路线、士气和其他条件做开关对照，同时核对预览、详情和真实行军。

## 技能树、经验和保存

武将详情右侧增加窄的“技能”入口，点击后向左展开抽屉。绑定规范武将编号，切换武将时更新；关闭详情或进入其他界面时收起。抽屉仅在武将详情显示，不共用地图光圈的显示许可。它与已有战绩条、F 一览是不同入口，手动收起，不通过鼠标焦点决定是否存在。

技能树至少分成属性、兵种、特殊效果三个分支。节点包含稳定 ID、经验费用、前置节点、等级、适用条件和效果。首版只列出已支持或明确待接入的效果；减伤、免疫、治疗和士气保护仍各有未核实结算入口，不能仅靠技能节点给它们标记“已生效”。

沿用当前斩敌口径：已记录敌方兵力减少，包含伤兵，1 人对应 1 经验。

```text
累计经验 = 当前存档累计斩敌
可用经验 = 累计经验 - 已消费经验
```

战绩中的斩敌总数继续保留，消费经验不减少战绩，也不降低现有百战精锐门槛。学习操作只在费用足够、前置满足时完成一次扣除与解锁，按钮不能重复提交。同一规则用于界面和实际效果。

现有存档内容哈希检查点能提供载入/保存基础，仍需新增经验消费、学习节点和特殊部队配置记录。普通与自动存档均须对应恢复，读旧档恢复旧技能和剩余经验。技能购买本身可能只改变插件数据，须处理原生内容哈希相同但插件状态不同的保存，不能直接覆盖同哈希下的旧技能记录；应增加槽位/分支与插件修订关联，并核实复制存档行为。现有统计从接入起累积，接入前未记录的杀敌不能凭空补齐。

建议先验证一个小闭环：高顺详情技能抽屉 → 显示当前经验 → 消费经验学习重骑机动 +10% → 出征预览与真实行军对照 → 保存、重启、读旧档。这个闭环稳定后，再接陷阵营按钮、独立费用与部队标识；全面扩展原生编号另作研究。
