# 当前 EXE 的人物编辑接口核查

分析样本 SHA-256：`604f5fe9bdd6dc2b813b93333aabeadefbad50afd2b4f71a11718b7363bca8ef`。
地址均为 RVA，运行时加实际模块基址。本轮没有调用这些尚未接入的函数；下列证据是静态核对，不能代替实机验证。

## 五维和忠诚

`0x394250..0x394313` 是一个以人物指针、选择器、数值为输入的设置路径：RCX 指向对象，EDX 为选择器，R8D 为数值。选择器 1..5 将数值限制在 1..100，写入人物 `+0x124..+0x128`。这不是只写一个字节：随后调用 `0x2f7430`，取返回对象 `+0x60 + 数值*8` 的表项，将该表项传入 RCX、能力索引传入 EDX，调用 `0x21df60`，将返回值写入 `+0x13c + 索引*4`。这些 DWORD 属于相关成长状态，不能忽略。

当前样本的 `0x21df60` 实际执行 ECX 的平方、再平方，以及除法和 `ECX*2000`；它不解引用 RCX，也不使用调用方传入的能力索引。没有观察运行时表项，尚不能确认这里接收对象地址还是专门改写的数值。不能直接认定函数损坏，也不能认定整条路径可以安全复用。

这条原生路径的 1..100 限制也不能当成字段完整范围。存储字段为 uint8；计划要求的自由编辑范围尚需结合成长状态、异常原值及当前 EXE 的实际读取方式核实。首版没有通过修改指令或跳过成长更新来绕过限制。

同一设置路径的选择器 6 写入 `+0x120` 忠诚字节；如果人物 `+0x196` 的 `0x2000` 位存在，则强制写入 255。`0x2c1d90` 另有减忠诚路径，同样检查该标志。因此 255 不能仅理解为普通玩法的“忠诚 100”，也不能忽略锁定标志进行任意赋值。忠诚编辑尚未单独接入。

`.pdata` 把该函数拆成 `0x394250..0x39429c` 和 `0x39429c..0x394309` 两段；后面的恢复寄存器与 RET 到 `0x394313`。不能仅凭第一段异常处理记录推断完整函数边界。

## 已学战法

初始化路径 `0x204630..0x204757` 和原生学习处理 `0x1d47d0..0x1d4c4f` 都使用人物 `+0x168` 的十个 uint8 槽位。学习处理在 `0x1d4a70..0x1d4aa3` 遍历新清单，限制槽索引 0..9 和编号 1..200，再写入对应槽位。

同一处理函数还减少书籍库存、修改据点相关数值、执行命令结算。这是正常玩法的整条学习命令，不符合“自由学习且不消耗书籍”的编辑要求，不能整体调用。它也没有证明替换、删除后所有缓存都会自动更新。十槽容量已确认，安全的自由编辑接口仍未接入。

## 官职

有效能力 getter `0x20ce20` 读取人物 `+0x11f`，从世界 `+0x77c20` 取得共享官职定义，再调用 `0x1d2990`。定义只读。

`0x36cb93..0x36cc0f` 是另一个较大函数的尾部，比较两个官职定义 `+0x37`，满足条件时把一个人的官职交给另一个人，并把原人物 `+0x11f` 写为 `0x49`。这段依赖前面的寄存器和对象校验，**不是可以直接调用的函数入口**。完整函数签名、任命约束、职务清理及其他调用关系尚未核实；不能截取尾部用于调换。

## 关系和名品

人物初始化 `0x205130..0x20530a` 清理两个各八个 uint16 的数组，以及其他关系相关字段；仅从布局不能确定数组分别对应哪类关系，更不能推出完整结义容量和互相清理规则。

名品持有者读取线索位于 `CItemData +0x4a`，有效能力查询会按人物编号筛选。该字段还参与序列化。授予、转移、收回是否同时更新位置、列表、任务状态和事件，尚未核实。因此没有开放直接改持有者字段。

## 当前限制如何传递给调用方

`s14_edit_capability_info()` 按操作返回可用性和具体原因；目前仅全目录个性编辑可用。提交不支持的操作会得到独立请求编号和“不兼容”终态结果，人物数据不变。该结果与排队请求分开存储，大量失败请求不会驱逐正在执行的结果。

这些限制是具体接口证据不足，不能仅把缺失功能标记成“待实机验收”。官职、关系、战法书、名品和基础属性仍需要接入和独立验证，完整候选包门槛保持关闭。
