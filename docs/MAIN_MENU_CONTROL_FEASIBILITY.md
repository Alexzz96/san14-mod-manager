# 主界面左侧新增原生控件：可行性检查

## 已核实的实现基础

检查本机 `SAN14PK_SC.exe`，SHA256 为 `604f5fe9bdd6dc2b813b93333aabeadefbad50afd2b4f71a11718b7363bca8ef`。以下地址均为 RVA，仅适用于该二进制及通过入口校验的兼容版本。

| 组件 / 入口 | RVA | 静态证据 |
| --- | --- | --- |
| `CMainCmdLayout` | 虚表 `0x13580e8`；初始化 `0x797900` | 使用原生 `00_02_00_mein_command` 资源，创建命令菜单子布局 |
| `CMainCmdLayoutBase` | 虚表 `0x1357dc8`；初始化 `0x797b50` | 使用 `00_02_00_mein_offset_20_pk` 资源，创建、定位并绑定菜单按钮 |

| 原菜单按钮 | `CCmnSwitchButton` 构造 `0x763cb0`；初始化 `0x767b00` | 原菜单分配 `0x190` 字节，通过虚表槽 51 接入父控件和行为组件 |
| 按钮区域 | `0x770dd0` | 设置原生按钮内部矩形，不能当作文字接口；原菜单命令名称为贴图 |

菜单初始化存在两组固定 6 次循环，分别填充子布局和按钮字段。原按钮还带有命令索引和菜单自身回调。因此不应只把数量改成 7，也不能将现有按钮对象直接复制后当作新命令使用。

## 建议实现方式

在确切主命令菜单初始化完成后，另建一个原生子控件，复用菜单按钮的资源和原生布局 / 行为接口，使用独立文字、独立事件回调。位置以“裁决”或父菜单的逻辑坐标为锚点，不能直接使用这张裁剪截图中的像素坐标。控件随父菜单隐藏、显示，并在场景退出时走原生生命周期管理。2026-10-10 实施补充：原命令名称通过贴图显示；新增文字应使用原生 `CCmnText`（构造 `0x77a300`，初始化 `0x7822a0`，文字设置 `0x78aff0`）而非 `0x770dd0`。

这一路径具备复用原生底图、字体和鼠标状态的基础。它仍需一个最小实机样例验证，不能把静态定位视为已经显示成功。
