# 主菜单“操演”原生占位按钮

dev.8 根据用户的实机截图处理矩形背景、层级和字号差异。读取本机 ScreenLayout.rdb 的原菜单资源确认 `000_cmn_com_clip_main` 是独立的弧形裁切贴图；原按钮自身的 21 个皮肤节点与新增按钮相同，因此更换按钮皮肤不能解决裁切。新版将新增按钮的原生绘制提交移至“裁决”的原生绘制回调之后，文字也在该处提交；两者在活动 UI 列表中的独立绘制回调不再提交第二份图形。保留 UI 注册以更新资源和接收鼠标。此修改用于接入原菜单的绘制区间，实际是否沿弧线完整裁切仍需游戏画面确认。

“操演”的原生文字字号从 32 改为 42，以接近原菜单贴图文字的可见高度。原菜单名称为预制书法贴图，尚未找到“操演”对应贴图，当前动态字体仍不能保证书法笔形一致。不能将字号调整视为字形已经完全匹配。没有修改游戏 RDB、原按钮数组或命令行为。

dev.8 测试增加绘制顺序（锚点、背景、文字）、独立回调不重复提交、不可见 / 父菜单注销后不绘制、返回值及 LastError 保留。静态检查覆盖新增绘制入口、两种控件的原生虚方法 3 和第六个 MinHook 接入。日志 `draw_after_anchor` 可确认绘制路径是否实际执行。专项测试和静态检查不能替代游戏视觉验收。

本地开发版在左侧主菜单“裁决”下方增加“操演”。当前为占位入口，点击不打开功能、不下达命令或消耗政令。原生外观、悬停和按下接入的实机视觉效果仍待验收。

按钮沿用 `CCmnSwitchButton`、`CMainCmdButtonBehavior` 的原生资源和行为，在确切的 `CMainCmdLayoutBase` 初始化结束后尝试创建独立子控件。资源绑定或动画尚未完成时，锚点可能仍在默认原点；原生菜单更新后会补建，已在接入前创建的菜单也能补建。分配或初始化失败后最多每秒重试一次。原来的六项布局 / 按钮数组、命令索引及事件回调均不扩充。原命令名称为贴图；新按钮隐藏这张名称贴图，以原生 `CCmnText` 显示“操演”。字体、绘制、缩放和鼠标反馈均使用游戏 UI。

位置以最后一项“裁决”的逻辑矩形为锚点：向左 28，向下一个按钮高度加 20；实机只读位置得到 `(45,781,160,64)`，父菜单为 `(0,0,960,1080)`。菜单更新后跟随锚点位置、显示和启用状态。越过父菜单边界时隐藏。私有虚表保留原生 RTTI、渲染和删除，只包装按钮删除以清除插件的弱引用。

dev.5 实机诊断确认控件已构造，按钮位于 `(46,781,160,64)`、文字位于其内部、可见标志均为 7，但没有进入活动 UI 列表（原生菜单按钮存在于列表 20，新按钮只在父节点子列表）。父资源布局只显示原先绑定的六行；父子关系不会自动注册额外控件。dev.6 完成构造后分别调用原生显示入口（虚方法 7），将按钮和文字加入 UI 管理器。父菜单资源清理入口会先调用两者的原生注销（虚方法 8），再进行资源清理（虚方法 5）和删除（虚方法 0）。原生删除析构仅释放对象内存，不能代替资源清理；额外控件不依靠原六行的布局来释放。分配 / 初始化失败也执行相应清理。

dev.7 对照本机 EXE 的原生实现反汇编，修正 dev.6 的输入状态错误：`0x76c800` 是虚方法 9 的鼠标离开回调，会清除按下 / 悬停位并发送离开事件，不能每帧当成启用设置调用。真正的启用接口为虚方法 25 `0x125f0`，只改动标志位 4。新控件改为原菜单同样的短初始化 `0x767b00`，再调用虚方法 52 `0x770d30` 绑定资源节点 1 的鼠标区域、虚方法 54 `0x770dd0` 设置范围。背景继续使用 `00_02_00_mein_offset_21`，没有另画背景贴图。

新增文字设为不参与鼠标命中。正常 / 悬停 / 按下 / 禁用 / 选中五个行为包装保留原回调及其命名动画，只在原回调后调用 `0x830fb0` 为原生字体应用原菜单调色板 25 / 26 / 27 / 28 / 29 的四角渐变。移除旧固定颜色 `0xff3b2b29`：游戏颜色按 `0xRRGGBBAA` 使用，该数值的透明度只有 `0x29`，也无法随原生状态变色。原生字号与布局字体仍用于“操演”，原五项名称本身是预制字形贴图，二者字形一致性需要实机比对。

额外按钮及文字跟随父菜单原生显示 / 注销入口 `0x793c90` / `0x794a50`，重复显示不重复注册，隐藏后清理不重复注销；透明度跟随“裁决”。日志新增 `hover` / `pressed` 回调计数，以确认真实鼠标是否到达状态机。
