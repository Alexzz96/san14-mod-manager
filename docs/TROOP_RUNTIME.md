# 陷阵营游戏接入 · 0.10.7 本地验证版

**0.10.8 当前 EXE 说明：**用户替换了游戏 EXE，直接交战调用目标从 `0x16a920` 变为 `0x257c370`。按用户要求，减伤适配留待后续；下面的 80% 是注册表设定，不代表已在换入的 EXE 验证实际生效。此次安装保留游戏 EXE，其余入口单独检查。

当前实现高顺专属陷阵营的出征流程，未接入技能树或经验消耗。实机验收尚待重新启动游戏后完成。安装器和源码均保留本地，未上传 GitHub。

## 使用与规则

1. F10 → Mod → 开启“扩展兵种 · 陷阵营”，默认开启。
2. 高顺 → 设定出阵部队，在兵种行第三个位置点击原生按钮“陷阵营”。橙色表示本次选择，与大戟、重骑互斥；再次点击保持选中，点击普通兵种可取消陷阵营。0.10.7 使用独立金色盾戟图标，原生按钮保留点击与选中逻辑。
3. 鼠标停在陷阵营按钮上时展示军费和效果，移开即隐藏，不再常驻白色说明块。费用是额外 2000 + 500 × 向上取整(兵力 / 1000)，另外仍支付原生军费。陷阵营最多出征 1000 人，额外费用为 2500。选择时自动收敛超过上限的编成人数；原生滑条、人数输入和士兵最大共用这个上限，确认与实际建队再次校验。切回普通兵种恢复原生人数上限。顶部原生“剩余资金”同步减去额外费用；不足时原生确定按钮不可用。这里只预览，成功建队前不扣实际资金。
4. 原生成功创建部队后才扣额外费用并绑定；仅选择、取消、资金不足或建队失败不会扣除额外费用。出征时再次核对资金和编成。
5. 陆上部队详情中的兵种标签显示“陷阵营”，水上仍显示原生水军名称。独立图标读取活动详情页的原生图标位置，只显示于实际已绑定的陆上部队。原生布局无法确认时保留原生图标，定位待实机核对。
6. 绑定部队显示为“高顺 · 陷阵营”；高顺的武将本名与其他普通出征保持原生行为。

## 存档与开关

- 不修改 `.s14` 游戏格式。原生成功保存后，用实际存档 SHA-256 为键，记录在游戏目录 `SAN14ModManager/troops/<hash>.s14troops`。
- 包含活动部队身份和待执行的特殊出征；读档立即停用旧绑定，再恢复该文件对应的记录。无对应记录的旧存档不自动获得陷阵营。失败读档恢复之前的绑定。
- 部队身份核对主将、原生兵种、部队编号、序号；所属城市字段仅作记录，不能用作身份标识；正常移除及重新创建清除旧绑定。新开局清空运行状态。
- 保存路径解析沿用现有本地 `Profile/<用户>/Saves` 适配；路径不明确或存在多个同名候选时拒绝绑定，不能跨存档猜测恢复。其他存档目录需要新增适配。
- 保存时需要同时保留游戏存档和对应插件数据。仅复制游戏存档到别的安装目录会丢失特殊兵种身份。
- 关闭 Mod 后保留记录、停用效果；重新开启恢复该记录。普通“移除插件”保留设置和数据；“彻底卸载”只清理可验证归属的兵种记录，保留未知文件。

## 接入位置与验证

`troop_runtime.c` 适配原生出征状态、编成预览、确认队列和成功建队；额外军费使用原生城市资金 setter。原生第三个预建按钮仅在它隐藏、且当前主将符合资格时复用，保持游戏的字体、底图、边框与点击控件，不创建外部选择按钮。切换武将、退出编成和关闭 Mod 时恢复原生控件。所有游戏函数都在自然运行的游戏线程回调中调用；悬停说明是穿透鼠标的辅助 Win32 窗口，受当前原生界面和插件窗口门控。

原生选择回调 `0x726280` 识别这个控件的精确指针；内层按钮和外层包装的原生编号置为保留的 0，让原生固定编号回调忽略它。实际编成仍写合法的大戟编号 1，插件字符串身份另行保存。刷新 `0x71ea00` 后恢复单选状态，兵种标签使用原生 `0x831e70`；预建按钮参数使用 `0x70d5a0`，显隐、可用和选中使用原生控件 setter。每帧只核对状态，不重复设置文本或初始化图片。0.10.2 不再逐帧写入选中状态：原生 `0x786260` 在鼠标按下时置 `0x100`，此时逻辑选中字段 `+0x188` 仍是 0；旧同步错误地清除按下标志，导致点击被取消。单选状态仅在初始化、原生编成刷新和选择回调完成后同步。

原生资金预览 `0x6ed740` 的返回值额外扣除本次已选择陷阵营的费用，原生顶部汇总 `0x719360` 和确认可用性 `0x721930` 共用它。取消出征、调整兵力和切换普通兵种都按当前编成重算；这个入口不写城市资金。

属性组合复用已有攻军/防御 hook，新增攻城、破城及机动入口。机动使用独立的 Windows x64 参数签名，不能当作攻军/防御/攻城函数调用。所有入口和直接调用的函数都先核对代码签名；不做游戏版本/整文件哈希匹配。

`test_troop_runtime.c` 在独立测试进程里模拟原生对象和回调，验证控件复用、三个按钮单选、重复点击不取消、切换主将不覆盖其原生第三兵种、关闭与退出恢复、逐帧无文本分配、悬停提示范围/鼠标穿透、资金预览不扣费、预览作用域、白字不变、五项倍率、一次扣费、资金不足、失败创建、普通编成覆盖旧选择、部队复用、保存/读档/失败读档和界面状态门控。离线核对 25 个适配入口、16 个私有 trampoline、4 个控件 vtable 方法，以及顶部和确认按钮调用资金预览的位置。这些测试不在游戏进程内执行，不替代重新启动后的实际出征验收。

启动日志 `troop_registry` 的 `engine_capabilities:127` / `gameplay_integrated:true` 表示适配入口已安装，不代表实机和平衡测试已通过。运行事件以 `plugin_troop_` 开头，记录选择、拒绝、成功出征、扣费和存档恢复。纯目录 CLI 的能力位仍为 0，因为它仅做设计校验与报价。

首次实机核对：1000 兵、城市资金 10600、原生费用 0 时，选择陷阵营后顶部剩余资金应为 8100，且只有陷阵营呈橙色；选择前设为 5000 兵，选择后应变成 1000，人数输入和士兵最大不能超过 1000。鼠标移开后说明隐藏。切换普通大戟/重骑恢复原生资金与选中效果；取消出征检查实际资金未变。成功出征检查人数不超过 1000、原生军费及额外费用各扣一次、陆上详情兵种标签为陷阵营、名称与属性；保存重启及回退旧档核对身份；最后用普通兵种再次出征确认未继承效果。


0.10.3 兵力上限使用原生 `0x6f5110(state, rowIndex)`，第二参数是出征队列行号；编成刷新前限制临时人数，提交和建队拒绝绕过上限的特殊编成。只限制新出征，不削减已在地图上的旧部队兵力，测试时回退出征前存档。部队详情刷新 `0x806ec0(page, army)` 完成原生绘制数据后，对已绑定部队的陆上基本页布局第 41 项文字设为注册表名称；普通部队、水军和其他页面保持原生显示。独立回归覆盖上限边界、普通兵种恢复、资金不误扣以及详情页切换。


## 0.10.6 数值与免疫修复

说明全文：所将七百余兵，号为千人，铠甲斗具皆精练齐整，每所攻击无不破者，名为陷阵营。人数和精整装备来自史料；本项目的传奇倍率及千人对两万人目标是游戏设计，不标为历史战果。

实机旧版证据：预览防御 570+1498、攻军 569+1412，出征后分别回退为 570+1153、569+1153。同一高顺部队编号 1、序号 0，创建回调绑定的城市字段 +0x14 为 0，随后原生改为 13。v1 附属文件保留这个字段和修订 1；身份核对排除可变城市，并继续检查世界、规范部队池、活动标志、主将、承载兵种、序号，移除及普通建队清除复用身份。原生建队期间，仅已通过编成/资金校验的临时身份能够使用倍率；失败创建不会提交身份或扣费。

破城原生 0x27c220 签名是 float(army, formation, actual, mode)，不是攻軍等入口的六参数形式。白字 actual=0 保留原生值；actual=1 基于原生计算结果一次乘倍率。新增 plugin_troop_attribute 日志记录阶段（1 预览、2 创建、3 已建部队）、身份、调用者、模式、白字/最终入口、原生值与插件值；同值去重、有限队列，游戏回调内不做日志文件 I/O。

混乱编号由本机 0x2bbfb0 分支和军纪个性对上：mode=0、计时 +0x23、拒绝类别 22。新增施加在采集开关判断之前返回原生拒绝码 22；0x293bf0 部队免疫查询亦返回相同类别。已有混乱在游戏线程自然属性回调中，使用原生负时长及计时归零规则清除；只在该调用作用域屏蔽类别 21/22 的清除阻挡和类别 9/10 的时长抵抗，其他类别与计时不动。绑定恢复/重新开启通过待处理标志在下一个自然回调清理，不从管理器线程调用游戏函数。模组中直接写入计时的额外路径仍需实机来源验证。

包围无效依据 0x15c05d 原生类别 55（万人敌/原生斗将）判断：原生把包围计数替换为 1 后调用 0x27b180。仅在相同调用点 0x15c084、真实计算和已绑定陷阵营时将计数改为 1，沿用原生惩罚公式。不会跳过攻击、修改主将个性槽位或改变其他兵种。两个免疫和真实强度在实机测试完成前始终标记待验收；只生成本地候选包。

## 强度验收（待执行）

平原、士气 100、粮道完整，无友军支援及其他插件增益。分别用陷阵营 1000 人对一支 20000 人、四支 5000 人，各做五次独立有效测试。每次记录存档、日期、双方身份、初始兵力、每次正向扣兵、伤兵生成/恢复/吸收、围攻计数、异常来源和拒绝结果。只累计真实正向兵力损失，恢复/吸收不冲减损失。目标每次三个回合以内击溃全部敌军、累计实际兵力损失不超过 200。固定使用上述倍率，不自动补偿。未达到则保存数据、输出差距讨论调参，不宣称达标。
