# 弓弩弹药测试版

当前 dev.17 默认25发、空闲日恢复2发；科技修正继续适用。更新保留已有配置。本机5发测试已结束。下文40发为历史频率基准与回归用例。

2026-10-13：基础科技已接入每名主将的容量、装填修正，弹药检查点升级 v2 保存不足一发的装填进度，并兼容原有 v1 文件。详见 [弓弩基础科技](ARCHER_TECHNOLOGY.md)。下文 40/2 仍是未强化基准。

按用户指定的十天回合、多目标结算基准设定容量 40。限定原生承载兵种 3（弓弩），双方部队均适用；弓骑、攻城兵器和其他兵种暂不处理。

## 当前规则

- 每支出征部队独立持有弹药，初始上限为 40 次普通攻击量。以每天对每个目标结算一次、连续十天为基准：四个目标消耗 40（全部），两个目标消耗 20（一半），一个目标消耗 10（四分之一）。按实际结算扣除，不预先按回合或附近敌人数扣除。
- 一次原生普通攻击结算消耗 1。反击及对不同目标分别发生的普通结算分别计数；战法、火烧、补兵和普通受伤不扣弹药。
- 弹药为 0 时，普通攻击结算返回该处理函数原有的完成状态 8，取消本次伤害及该函数中的后续攻击结算；不修改部队兵力、攻击属性或伤兵字段。原生外层动画可能仍播放，需实机确认。
- 一个完整游戏日没有成功执行普通攻击，下一日的原生调度将弹药恢复 2，最多恢复至上限。空弹时被取消的攻击不算成功攻击。暂停、移动镜头、重复刷新、重复同日调度不恢复；关闭功能期间和未知日期跳跃不补算。
- 第一次启用时已有弓弩队伍初始化为满弹。部队退场、换主将／序列号、世界切换、新游戏清理旧身份，避免槽位复用继承别队弹药。

## 显示与接口

地图上在士气条下方显示蓝色弹药条，空弹时边框变红。使用原生地图标记当前士气图元第 87 项的实际变换计算位置，保留原条宽度，下移并留出 3 个页面单位间隔；该素材在当前用户截图对应队伍中只读核对为 60×8。对局部模板、离开头像范围或不可读图元隐藏附加条。

附加条通过已有单个 D3D11 Present 渲染器绘制，跟随 1920×1080 页面坐标及游戏缩放。它是新增绘制内容，不是新 Win32 窗口，也不覆盖或修改原生士气图元。当前场景、窗口、原生页面、部队身份及标记绑定均在绘制前复核；详情页、对话框和失效采样不显示。渲染后恢复 D3D 状态。

普通结算入口为 `0x166760`，原生日调度入口为 `0x15bb40`；安装前核对入口字节及 `0x16685c` 普通伤害调用。`0x257c370` 使用调用方 RBP 作为隐含第六参数，因此不对它安装 C 钩子。当前整合包的 `0x2578bfd` 会调用普通结算入口，其现有包装逻辑仍保留。

## 存读档

不扩展原生存档格式。成功存档后在 `SAN14ModManager/archer-ammo/<原生存档SHA256>.s14ammo` 保存附加检查点，包含弹药、部队身份及当天是否开火。文件有独立校验摘要、版本、长度和范围验证；不序列化运行地址。读同一存档恢复相同余额，失败读档恢复读档前的余额。没有有效附加文件的旧存档初始化为满弹；不能据此恢复首次安装前的历史消耗。

## 配置和记录

测试安装启用以下配置；总开关仍控制实际生效。容量和恢复值在启动时读取。读旧检查点时使用当前容量，并保留已消耗量（旧上限减旧余额）；例如 13/30 转为 23/40。降低容量时余额最低为零，重复读档不额外补弹，原检查点文件直到下一次正常存档才更新。

```ini
[Troops]
ArcherAmmunition=1
ArcherAmmoCapacity=40
ArcherAmmoRecovery=2
```

插件日志新增 `archer_ammo_ready`、`archer_ammo_spent`、`archer_ammo_empty`、`archer_attack_observed`、`archer_attack_day`；地图渲染记录增加 `ammo_draws`。日志队列若有丢失，会输出 `dropped`，计数不能作为完整的攻击频率证据。

实机黄祖（260）在 210 年 11 月 1—10 日记录 17 次普通结算，两个目标分别 9 次和 8 次，大部分有记录的日期为每天两个目标各一次。11 月 3 日没有整日日结算记录，因此该样本不代表固定每回合频率。以 40 作为用户指定的容量基准，替代首版“连续三个回合”的容量目标。

## 离线与手动验收

`test_archer_ammo` 检查四目标十天耗尽、两目标十天剩一半、旧容量迁移保留消耗、逐次扣除、耗尽取消伤害、空闲恢复 2、开火日不恢复、重复同日和暂停不恢复、上限、部队隔离、槽位复用、关闭期间、存读档余额、失败读档回退及附加文件校验。`test_map_effects` 检查原生条坐标、局部模板拒绝和缺失图元；`test_map_render` 用 WARP 检查满、半、空条像素及渲染状态恢复。完整验证另检查当前 EXE 的入口字节和独立 MinHook 跳板。

游戏由用户手动测试：确认弓弩士气条下出现蓝条；让部队持续普通交战观察下降；验证十天四目标耗尽、两目标消耗一半，以及耗尽后无普通伤害及空闲恢复；切换部队、移动镜头、打开并关闭详情；存档、继续消耗、重读核对余额。逐目标扣除和空闲恢复已有实机样本，耗尽行为、新容量迁移画面及各分辨率仍需手动验收。此改动仅为本地测试 DLL，不宣称发布包的清理／重置工具已管理新增附加文件。
