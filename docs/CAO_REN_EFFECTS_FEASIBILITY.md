# 曹仁地图特效与悬浮说明的可行性

后续进展：0.9.5 已完成本地实现与生产只读定位核对，安装后的显示验收仍待完成；见 [地图特殊效果](CAO_REN_MAP_EFFECTS.md)。以下保留实现前的定位分析。

本次只定位、采样与分析，没有安装新的地图特效，也没有改变游戏状态。实机 PID 17252、0.9.4；玩家确认攻防增幅有效。日志已记录部队 29 的三次攻军和三次防御战斗调用，每次返回为该次原生结果 × 1.10；完整回合与关闭开关对照仍未单独验收。

完整 UI 注册表调查是一次性只读定位，读取约 1.55 MB、约 69 ms，扫描达到预设上限，不能宣称遍历了全部对象。正式模块应只解析已定位的相关容器，缓存有效标记并做身份复核；不在每帧扫描全注册表。

## 建议的第一版

1. **紫色外圈**：保留头像与原生势力边框，在外侧增加细紫色圈和轻微柔光，内部透明。可选缓慢呼吸动画，不遮挡士兵数字、状态圆点和选中标记。
2. **右侧效果卡片**：显示在原生个性列表下方，即玩家截图标出的右侧空白区。标题“特殊效果”，内容“攻防强化”“攻军 +10%”“防御 +10%”“当前生效”“来源：Mod”。其他武将、空地、增幅关闭或原生悬浮收起时隐藏。
3. **开关关系**：在“曹仁攻防增幅”Mod 下添加“地图头像光圈”“悬浮效果说明”两个子项。关闭显示子项不会改变实际属性；关闭父 Mod 同时停止增幅并隐藏显示。

视觉显示读取当前实际启用状态，不能仅凭配置文件中选择开启就显示“生效”；入口未接入、总开关关闭或部队身份失效时不得亮圈。

## 接入方式

优先使用独立的小型透明叠加窗口，复用现有游戏窗口定位、缩放和隐藏机制。光圈与说明都不抢焦点，鼠标点击与悬浮继续交给游戏。柔光需要带逐像素 alpha 的绘制路径，现有整窗透明度不能直接当作柔光实现。

光圈跟随原生标记的屏幕位置，不根据棋格手工推算相机投影。右侧卡片跟随原生摘要和个性列表的真实布局，而不是固定截图坐标。切换部队、读档、部队消灭、离屏、收起原生 UI 或切出游戏时清除对应显示。实际显示更新安排在插件工作线程，原生结算路径不绘制、不延时等待。

建议先做视觉叠加；直接扩展原生个性条目、替换势力边框或复用原生战法动画会涉及资源编号、对象生命周期和显示条件，仍需更多核对。当前不能把新特效伪装成“铁壁”或其他原生个性。

## 可以逐步扩展的效果

| 内容 | 当前可行性 |
| --- | --- |
| 头像外圈、柔光、呼吸、角标、效果名称、颜色区分 | 已有显示位置基础，实施后需镜头与交互验收 |
| 多条效果列表、来源、倍率、持续时间与层数展示 | 可以由插件统一效果数据驱动；目前曹仁增幅是开关控制，没有持续时间或层数 |
| 曹仁实际攻军、防御 +10% | 已实施，详情显示和实际交战调用已取得证据 |
| 斩敌门槛、地形或回合条件触发 | 可结合既有战绩与部队数据增加条件，但本次不实现，也不补算历史战绩 |
| 攻城、破城、机动增幅 | 属性计算位置已定位，尚未接入和验收；机动还有本地修改分支 |
| 混乱/挑衅免疫、伤害减免、治疗、战法增强 | 原生存在相关机制，资格、概率、来源与结算位置仍需专项验证，不能当作已支持 |

以后用统一效果记录表达效果 ID、作用部队/主将、来源、激活条件、倍率、颜色、图标与期限；计算、地图显示及悬浮说明共享同一状态，避免三个界面各自猜测效果是否生效。运行地址和屏幕坐标不写进存档。

## 实施后的验收

核对曹仁与其他部队、增幅开关和两个显示子开关、镜头移动/缩放、正常与简略/编组显示、窗口缩放与留边、悬浮切换、点击穿透、离屏、部队消灭与重新出征、读档及完整回合。当前报告是可行性定位，不代表这些视觉功能已经完成或已验证。
