# 弓弩基础科技 · 本地测试版

第四页沿用原生武将立绘与身份区域，右侧展示五列、每列三级的基础节点。点击技能打开原生控件确认浮窗；确认后消耗 1 点基础点数。每名武将最多 8 点，不分培养组；任意上一阶已学习节点都可以开放下一阶，因此允许校弦接固位。已学节点不能重复学习。本次学习不收军功或经验，不提供返还点数操作。

仅原生弓弩（承载兵种 3）实装。其它兵种可以切换查看，但不能学习。当前自势力武将且具有弓弩权限才可确认学习；学习记录随武将保留。进阶战术、传承兵种及射击战法的新机制均未加入。

| 脉络 | 节点 | 每阶独立增量 | 满列累计 |
| --- | --- | --- | --- |
| 攻军 | 校弦、劲弓、破阵 | 攻军 +5%/+10%/+15%；防御 −2.5%/−5%/−7.5% | 攻军 +30%、防御 −15% |
| 守备 | 护具、固位、列盾 | 防御 +5%/+10%/+15%；攻军 −2.5%/−5%/−7.5% | 防御 +30%、攻军 −15% |
| 机动 | 轻装、疾退、游射 | 机动 +5%/+10%/+15% | 机动 +30% |
| 容量 | 扩匣、备矢、重箭匣 | 每节点上限 +10，基础装填速率 −10% | 基准 40/2 变成 70/1.4 |
| 装填 | 轻匣、速装、轮换装填 | 每节点上限 −5，基础装填速率 +25% | 基准 40/2 变成 25/3.5 |

同类基础百分比先相加，再对原生及既有 MOD 计算后的实际部队属性乘一次。攻軍强化作用于攻军属性，不增加攻城或破城；防御反过来扣攻军，机动只改变机动。原生白字基准（actual=0）不改变。新增强化不覆盖任何原生属性字段，不增设攻击/防御/机动钩子，复用已有原生 getter。

容量和装填基于已有配置 `ArcherAmmoCapacity` / `ArcherAmmoRecovery`；默认 40 / 2。双方弹药机制仍适用，只有学习了基础科技的主将拥有对应强化。完整游戏日无普通攻击才积累装填，暂停、同日重复刷新和开火日不补给。不足一发的进度以整数百分之一保存；例如 1.4/日，五个连续空闲日恢复 7 发。两列满级合计 55 上限、2.9/日。

对已出征队伍调整容量时保留已经消耗的数量，不把学习等同于补满弹药。上限提高会增加相应储备，上限降低时余额最低为 0。现有普通攻击的零弹拦截继续生效；射击战法的零弹拦截并未在本次实现。

## 保存与开关

关闭详情仍保留强化。正常保存游戏后，稳定武将 ID 和学习位集合写入 `SAN14ModManager/archer-tech/<原生存档SHA256>.s14tech`；不扩展本体存档结构。读取同一存档恢复强化，失败读档保持原状态；没有有效附加文件的旧档清空学习。新游戏不继承上一个战役的点数。新增附加文件有独立版本、长度、SHA256 及前置/点数验证。

弹药 `.s14ammo` 升级为 v2，以保存不足一发的装填进度，同时兼容已安装 v1 检查点。先恢复科技再恢复弹药，防止已学容量在读取余额后重复加弹。

`[Troops] ArcherTechnology=1` 默认开启基础科技，总开关和 `ArcherAmmunition` 同时控制生效。关闭科技后保留已学记录，但数值回到原计算；重新启用恢复强化。相关入口未全部通过签名核对时不允许学习。

## 验证与手动验收

离线检查：跨列前置、8 点上限、独立增量、仅自势力学习、武将/兵种隔离、原生实际属性链路只调用原函数一次、开关恢复、关闭重开保留、保存/读档/失败回退、旧弹药文件迁移、1.4/日累积、开火日不补给、确认浮窗隐藏输入与分配失败回收。完整报告在本次独立构建目录 `native/build-archer-basic-tech-final/verification.json`。

游戏仍由用户手动验收：

1. 演武入口打开科技树，选择可用弓弩武将；查看五列节点及确认浮窗。
2. 学习校弦后可以学习固位；合计学到 8 个基础节点后不能再确认第九个。
3. 已出征弓弩攻军、防御或机动随强化改变，切换主将与其他兵种不串用。
4. 容量列与装填列改变地图弹药条上限及完整空闲日恢复速度；开火日、暂停不恢复。
5. 关闭重开、切换武将、保存重读后保持对应记录；返回地图后原有按钮正常。
6. 当前高分辨率、1080p、窗口模式检查浮窗、文字和鼠标命中。

本版为本地测试 DLL，原生图标、场景徽章、确认浮窗及实际战斗画面尚须手动检查。现有发布版清理工具未在本次扩展到 `.s14tech`，不要把旧清理工具当成科技重置工具。

本地测试版改用 840×650 的独立暗色原生面板，保留原生角色区域。顶部显示当前兵种与基础点数；五条脉络带不同主题色、定位说明和圆形技能徽章。弓、盾、靴、箭匣与装填箭头由游戏原生矩形图元组成，使用原生场景登记与释放，不依赖外部贴图、字体圆圈或浏览器。
