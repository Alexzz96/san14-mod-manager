# 0.9.9：地图光圈仅在主地图显示

## 0.9.9 的后续修复

0.9.8 仍会在“擢用”等未收录的原生界面覆盖面板。后台地图没有销毁，地图头像、注册表与详情句柄不必改变，因此不能把这些信息当作主地图正在显示的依据。

本地只读核对发现，原生 `0x509bd0` 使用 `0x19e6330` 状态管理器的 `+0x10` 深度和 `+0x20` 数组判定栈顶。主地图规划的栈顶为 `CUserStrategyState`（虚表 `0x12cc498`），擢用会在它之上压入 `CStrategyEmployState`（`0x132c028`）。地图行军更新 `CProgressState`（`0x12cc760`）同样使用原生栈顶判断。

新版以栈顶作为正向许可：只接受正常生命周期 `+0x6c == 3` 的规划/行军状态，规划还要求 `+0x470 == 2`；其他类型、读取失败和阶段切换都隐藏。状态栈容量和深度有上限，采集前后复核栈顶、数组与深度。Present 在每帧读取同一状态，并比较工作线程的绑定，几何采集完成后再次复核。进入任意未知界面同样会被拒绝，不需要为每一种菜单另列禁止项。特殊效果说明与光圈共用这一许可。

独立测试覆盖同一注册表下进入擢用、情报及未知状态、生命周期与规划阶段变化、规划切换到行军后获取新绑定、采集期间栈变化，以及返回地图恢复；保留 1024 个移动帧和 WARP 绘制验证。实机只读记录位于本地分析目录的 `scene-current.json`、`scene-recruit-confirmed.json`，不打包。没有新增游戏钩子、远程调用或数据写入。

以下保留 0.9.8 的修复记录。

用户在部队详情中看到地图光圈仍画在“命令/目标”附近。只读探针在该界面确认原生部队详情已经处于模态状态；姓名显示和百战精锐资格属于另一条正常工作路径，本次只修复绘制可见性。

## 原因

0.9.7 的工作线程在原生数值解析条显示时暂停地图采样，却没有把同一阻挡状态传递给 D3D11 Present 绘制模块。暂停路径保留了旧帧，发布函数又用当前时刻不断延长旧位置的有效期。缓存尚未收录新详情对象时，逐帧模态检查无法补救，因此旧地图头像的位置持续叠加在详情画面上。

## 修复

- 打开管理器、F 武将清单、回合报告、原生详情数值条/战绩条时，工作线程向绘制模块发布停用状态，并清除旧绑定。
- 无效、缺失或明确模态的帧不能保留旧位置。只保留真实采样的时间，重复发布不能延长有效期。
- 原生部队/武将详情模态仍逐帧检查，关闭插件详情条也不会取消原生检查。缓存指针不可读或类型不符时停止绘制。
- 逐帧验证原生详情上下文的注册表、句柄、索引与对象链头。采样后进入新界面时，先停止使用旧坐标，等待工作线程采集该界面。
- 返回地图重新采集有效部队，继续使用当前画面中的头像外框浮点坐标，不恢复外部光圈窗口或多处坐标比对。

百战精锐的姓名、5000 门槛、攻防 +10% 和生涯存档数据均未改变。此次未增加新的游戏计算钩子。

## 验证

独立测试覆盖阻挡时清除绑定、模态/空帧清理、旧采样不续期、返回地图恢复、采样后切换原生详情上下文和模态读取失败。保留 1024 个分数坐标移动帧、缩放、WARP 光圈像素、图形状态完整恢复和缓冲区重建测试。

只读现场记录保存在本地分析目录 `analysis/career/map-effects/overlap-0.9.7.json`，不随安装包或公开源码提供。新版本安装后的详情可见性和地图恢复仍需实机核对。
