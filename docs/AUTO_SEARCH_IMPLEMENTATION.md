# 0.4.3 本地自动探索实现

源码与构建仅位于本地 `E:\314 mod\san14-mod-manager`，没有向 GitHub 推送。本模块采用固定 RVA 加实际指令校验，不以游戏版本号或整份 EXE 哈希阻止安装。

## 触发与原生调用

`CUserStrategyState::update`（0x3F8EF0）提供当前玩家规划上下文；0x3FCF20 的调用来源必须恰为确认推进分支的返回地址 0x3F9446。这个分支已消费确认标记，随后才进入阶段清理。其他调用及取消确认均不会派遣。按世界、日期、势力去重，避免连续帧重复提交。

通过当前世界 0x85130 的设置与日期、0xDE40 的势力模型和 0xDCA0 的对应数据构建输入。0x2034E0 的原生城市迭代器、0x159880 / 0x159FA0 的原生路线容器、0x27E6D0 / 0x20E710 的距离计算复现原生自动探索缓存。0x65CF80 接收三个原生 UI 索引进行候选筛选与排序。临时容器在当前调用结束时使用原生析构函数释放。

读取 0x62AB00 的实际政令费用，按剩余政令截取候选。0x631AA0 选择目标区域，0x1D6C30 提交原生 `CCmdActionSearch`，由游戏设置任务、扣费并保存。只有武将由空闲变为原生任务忙碌状态才计入派遣人数。

## 结果与统计

0x1C91E0 的探索执行入口建立线程局部结果上下文。0x258860、0x257B20、0x258700 分别提供武将、名品/战法书和金钱候选；最终结果在该执行函数调用 0x28A620 的真实完成位置捕获。0x835550 原生日志函数提供中文发现明细，全部原生参数与返回值转发保留。所有结果按玩家规划时确定的势力过滤，不能用行动阶段临时的活动势力代替。

插件不以城市金钱差分估算搜索收益。长途任务跨回合存在于原生任务管理器中；统计在实际产生结果时加入，返回过程不会调用新的结果捕获。统计包含本势力自动及手动探索，便于与原生报告核对。

游戏线程只执行本来由原生自动探索执行的筛选、路线与派遣调用，并向 512 项有界队列复制记录。Win32 窗口、2 秒提示、配置读写、UTF-8 日志与 UTF-16 最近报告由插件工作线程处理，不阻塞游戏等待提示。队列溢出会停用后续自动派遣并明确标记统计不完整。

## 已完成验证和边界

- 独立模型验证：取消与关闭、10000 次重复帧、日期倒退、世界改变、费用与候选预算、四种结果、长任务计入、成功与失败姓名地点、超过 64 条明细、中文报告保存读取。
- 隔离原生接口模拟：实际派遣代码、路线容器、三组参数 ABI、原生拒绝、扣费不足、无候选、析构配对、确认调用来源、五种结果含未发现、12 参数日志转发、返回值不变、排除其他势力。
- 私有代码副本验证：8 个新钩子入口均可建立 MinHook 跳板，检查原游戏 EXE 的字节，不向运行游戏写入。
- 一次 167 字节只读探针核对本机当前势力为 1、政令为 14，耗时约 0.23 毫秒。无调试器、暂停线程、注入或进程写入。
- 原有墙体、提示、管理器和安装/卸载回归测试继续执行。

以上不能代替实机验收。安装后仍需核对原生派遣、回合日期、2 秒开始提示、发现明细及长途任务；独占全屏、多个人类势力轮换和其他 EXE 构建未作实机保证。单次派遣的耗时记录为 `elapsed_ms`，用于核对是否存在异常结算延迟。

## 0.4.0 闪退及 0.4.1 修复

2026-10-07 的实机转储记录 `0xC0000005`，故障 RVA 为 `0x2F614B`，执行 `mov rcx,[rdx]` 时 RDX 为 0。调用栈返回到 0.4.0 DLL 的城市遍历位置；迭代器势力字段为 1。0x2034E0 原生构造函数和 0x67AA1E 的原生遍历均将“当前城市指针槽”作为第二个参数传给虚表第 1 项（0x2F6130），插件此前错误地以单参数函数调用它。0.4.1 显式传递 `(&iterator, iterator.current)` 并检查下一槽可读性，补充结构大小与偏移的编译期校验。

优化构建的 Zig C 编译器定义 NDEBUG，导致新增探索测试中的 assert 未执行，之前的探索模拟验证证据不足。测试构建现明确使用 `-UNDEBUG`；探索模型与桥接测试在断言关闭时直接拒绝编译。原有使用 REQUIRE 的测试不受该宏影响。

新增回归从本机 PE 读取完整的 147 字节原生城市构造函数及 55 字节原生筛选函数，置于独立测试进程的私有内存。原生的虚调用与 RIP 相对世界指针都指向该测试的仿真数据，验证 52 个城市中的势力筛选、跳过中间及末尾外势力城市、空迭代器、原生路线与派遣。另一个隔离子进程重现旧版 RDX=0，在相同 RVA 捕获相同空地址访问错误。这些测试不加载游戏 EXE，不附加运行中的游戏，不修改存档。

闪退还留下了无窗口、0 线程的报告残留进程；终止后它的 PID 仍暂时可枚举。安装检测现在忽略无执行线程及已终止的进程，活动游戏与读取失败的活动进程仍阻止替换。使用复制到临时目录的独立测试程序验证活动进程阻止安装、终止后持有进程句柄也不阻止安装；文件占用及事务回退检查继续执行。

## 0.4.1 后续闪退及 0.4.2 修复

两次后续实机转储（PID 54228 和 64168）均在 RVA 0x65DCD0 的 `mov [rax+rdx*8],rcx` 写入时产生访问异常；RAX 为 0，武将编号分别为 123 和 393。城市遍历已经通过，故障出现在原生候选函数为武将记录目标城市时。

全局 0x1FC9520 存储的是目标表指针。原生搜索界面在 0x66C2F9 准备 0xBB88（6001 × 8）字节，经 0x3A57B0 分配，在 0x66C303 写入该全局；界面退出时 0x668612 读取表指针，经 0x3A57C0 释放后置零。无界面的自动探索跳过了这一步，且插件之前还错误地将该全局当作内联数组读取。0.4.2 在候选筛选前绑定独立零初始化表，读取 `targets[person_id]`，完成后恢复先前表指针。仅插件所分配内存使用进程堆释放，不交给游戏分配器。

原生退出路径还遍历世界 0x100 的全部武将链表，清除 0x196 的 0x40 临时标记并清零 0x1F4 天数。无界面派遣现在预先检查并保存这些字段，结束后恢复原值；命令新设置的 0x01 忙碌位不会被回滚。所有入口失败及无候选路径均释放已创建的临时容器。武将编号在调用原生筛选前检查，超过 6000 时停止派遣。

另行检查发现 0x835550 日志函数返回日志对象指针，原钩子的 int 返回值会截断 Win64 指针。现将返回及整数参数槽使用 uintptr_t 完整转发，测试使用带高 32 位的参数和返回值确认不会截断。

私有回归除完整城市构造和筛选函数外，还执行 0x65DCC1 至 0x65DCD4 的 19 字节原生目标写入代码副本；其 RIP 相对目标表地址映射到独立测试镜像。负向子进程在编号 393 时复现 0x65DCD0 写入 0xC48 的同一访问异常；修复后验证完整派遣、编号 6000、已有表保留、只读表槽拒绝以及武将临时字段恢复。原生候选排序与派遣 API 仍由模拟回调验证，这不等于完整游戏结算验收。

派遣阶段日志 kind=6，type=0 至 4 分别对应开始、路线及临时表就绪、候选生成、派遣结束、清理结束。开始提示显示 2000 毫秒且不在游戏线程中等待。日志可帮助下次实机验证定位最后完成的阶段。

## 0.4.3 完整结果弹窗

结果回调复制执行武将及目标区域的 UTF-16 名称。静态证据：CPersonData 虚表为 0x12A00D0，0x20C270 的原生姓名格式器使用 +0x12 和 +0x24 两个固定 9 字符字段，通过 `%s%s` 合并；CAreaData 虚表为 0x129FF98，0x20F3D2 的原生名称查找返回区域对象 +0x10。读取前校验类型和内存范围，不新增原生函数调用或修改游戏字段。信息在探索候选回调前复制，成功和未发现均可定位执行者与地点；无法识别时明确显示未识别，不猜测。

结果事件新增 actor/location 字段，日志同步保存。归并器为所有已完成事件生成明细，type=0 为“探索失败（未发现任何收获）”；成功记录保留原生发现及擢用文本，清除 ^05 等颜色指令。明细在工作线程按需扩容至 6001 条，超限或内存不足明确标记部分记录未保存。报告重置释放旧内存；弹窗使用独立副本，后续 BEGIN 不影响正在查看的报告。

结果窗口保持 WS_EX_NOACTIVATE，移除用于普通提示的 WS_EX_TRANSPARENT，命中测试返回 HTCLIENT。WM_LBUTTONUP 隐藏并清除持久状态；WM_MOUSEWHEEL 调整绘制偏移，滚动范围覆盖最后一条。内容按真实字体与窗口宽度测量，限制在游戏客户区内；结果不自动倒计时。离开游戏暂时隐藏，返回时恢复未关闭报告。开始与墙体提示继续使用原定时、穿透行为。独立测试验证 120 条结果、末尾可见、点击关闭不恢复及 192 DPI 绘制；实际游戏鼠标交互仍需验收。
