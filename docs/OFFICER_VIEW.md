# 武将一览 0.8.3：使用与数据边界

保存并退出游戏后安装本地 0.8.3，重新启动、载入存档，点击地图窗口后按字母 F。F10 仍为功能管理器；在 F10“Mod”展开“武将情报”或外部管理器中可启停武将一览。此项是只读视图，不依赖自动搜索或墙体规则的总开关。

搜索框匹配姓名、字及个性名称，支持中文、无声调完整拼音及拼音首字母，不区分大小写，例如“曹操 / caocao / cc”“张嶷 / zhangni / zy”“山战 / shanzhan / sz”；空格分隔的条件同时满足，例如“张嶷 山战”。可筛选全部势力 / 自势力、城市关隘 / 出征 / 执行任务，默认只列现存武将；“全部记录 / 历史”包含未登场、死亡等记录。未发现武将也包含在现存列表中，以相应身份显示。

点击五维或总和表头切换排序，也可在顶部选择排序项目和升降序。姓名、势力、身份、位置、个性、部队兵力、野心、情义、忠诚同样可排序。野心与情义按游戏显示 1～5 级；忠诚保留原值，无所属或不适用的武将显示“—”。字段来源见 [内心字段与拼音搜索](OFFICER_CHARACTER_FIELDS.md)。默认“战斗统计”，点击标签或按 Tab 切换到“原始数据”。姓名、势力、所在位置固定在左侧，其他字段按标签显示。两侧同步纵向滚动及选中行，列宽按窗口分配，无需横向滚动。切换保留搜索与筛选，各页记住排序；底部武将档案已移除。当前的五维是**基础能力**，未计算官职、名品、受伤等加成或减成。执行任务中的“归属据点”不是未经核对的任务目标。

每次按 F 打开列表时采集一次，窗口打开期间不定时更新。搜索、筛选、排序及标签切换使用这次快照；关闭后重新按 F 打开才刷新。读取失败时保留上次列表，提示返回地图后重新打开，不自动重试；切换应用、搜索和下拉框不再触发自动隐藏。窗口不长期置顶覆盖其他应用。读取不向游戏写入、不调用游戏内部函数、不暂停游戏线程；处于载入或记录变化中时保留上次列表并显示等待提示。刷新尽量保留选中武将及阅读位置。弹窗不主动暂停回合结算；对照时请用游戏自身暂停操作。

点击右上方“关闭”、标题栏 × 或按 Esc 收起，从游戏主窗口再次按 F 也能收起。显式关闭功能开关或 F10 切换管理器会收起。F 只在游戏主窗口聚焦时注册，弹窗输入框中的 F 是正常字符；此快捷键范围判断不控制窗口自动关闭。若系统中有其他程序占用了 F，启动日志 `officer_input` 会显示注册错误；`officer_toggle` 记录实际打开及首次读取结果。

## 本次验证

2026-10-08 在当前测试存档的暂停地图上，生产模型通过只读进程权限取得 1,400 条有效武将记录，默认现存列表为 599 位；一次读取约 6 ms、1.71 MB，没有读取错误或变化冲突。张嶷、曹仁的出征兵力和位置已对照现有测试数据；军团编号已转换为所属势力，曹仁正确归到曹操势力。原生字典用于个性、战法和身份名称。

0.5.2 的 138 项独立断言覆盖拼音、多音字、首字母、内心等级及忠诚边界，并覆盖搜索、筛选、排序、未知计数、存档分支接口及原生窗口行为；既有规则、自动搜索、弹窗、安装与卸载测试通过。安装后的游戏内 F、输入搜索、关窗及跨回合刷新仍需实际验收；只读核对不能替代这一步。

0.5.0 现场反馈为 F 打开后立即消失。日志确认读取 1,400 条成功、随后前台判断为离开游戏；私有窗口复现可调整面板的 `GA_ROOTOWNER` 返回面板自身，尽管其 `GW_OWNER` 是游戏。0.5.1 按用户要求去掉这项自动隐藏，测试覆盖窗口失活超过 1.2 秒仍保留、搜索 / 下拉框 / 读取失败均不关闭，以及按钮、Esc 和 × 关闭。本次用户已确认手动关闭修复有效；新增界面、拼音及内心信息仍需在更新后验收。

## 战绩接入

`native/officer_model.h` 定义 `S14OfficerCareerProvider` 版本 1：通过战役 ID、存档分支 ID 与武将 ID 获取 `S14OfficerCareer`。每个计数保留独立有效位；F 表格用 `s14_officer_count_value` 将没有有效记录的计数投影为 0，按显示的数值排序。有效累计保持原值，后台未核实事件不据此变为有效事件。统计字段包括击杀武将、击溃部队、击杀士兵及伤兵；当前表格已预留击杀与击溃排序。

0.7.1 通过 `battle_stats.h` 版本 1 提供者接入杀敌数（含伤兵）、击溃、自身覆灭、自身损失及击伤次数，按世界身份和武将编号映射，全部支持的势力参与累计。F 打开前排空已提交事件，再读取快照；F 表格未记录项显示 0，后台仍区分未知与已核实的零值。计数与真实存档内容摘要绑定，成功载入恢复检查点；不补算接入前历史，不猜测延迟火伤归属。具体口径、备份方式与验收见 [存档战绩](BATTLE_CAREER.md)。原有 `S14OfficerCareerProvider` 保留，用于未来已核实的武将击杀、实际阵亡等字段。

## 开发接口

`s14_officers_capture(read, context, image_base, snapshot)` 接受有边界的只读回调，解码武将、原生字典、所属势力及部队。`s14_officer_matches` 和 `s14_officer_compare` 可独立调用；`s14_officers_attach_career` 只接受版本、战役和分支绑定完整的提供者。UI 与游戏采集模型分离，后续可增加分组、导出与更多情报字段。

每次读取限制 20,000 次调用 / 8 MiB，单次不超过 64 KiB；检查类型表、身份编号、取值范围、单行二次读取、指针表以及世界 / 日期状态。数据不稳定时丢弃本次结果。这是变化检测，不是游戏线程冻结下的全局原子快照。字段未识别时不通过调用未经验证的游戏函数补齐；战斗计数显示 0，原始属性不适用项显示“—”，原始有效位保留。

独立模型测试：`native/build/test_officers.exe`。开发诊断：`native/build/officer_probe.exe PID output.json`；此工具只读指定 SAN14PK_SC.exe 进程，并不安装插件。玩家仅需要安装包中的管理器。

配置：`SAN14BuildLimit.ini` 中 `[Views]` / `Officers=1`，设为 0 关闭入口；更新保留其他已有设置。

## 原生武将详情战绩条

0.7.1 打开游戏原生武将详情时，在右侧上方显示当前武将的累计战绩，与 F 列表共用计数。关闭原生页面或切换应用时隐藏，鼠标可穿透。F10“更多拓展”提供独立开关；F 列表仍只在打开时刷新。新增效果独立测试通过，仍需实机验收；详见 [原生详情条](NATIVE_OFFICER_DETAIL.md)。

## 0.8.3 战绩与时间线

战斗列统一四字名称，隐藏单挑总数与不同俘虏人数，增加杀损比值（斩敌 ÷ 折损）。斩杀敌将仍为预留接口，未核实记录显示 0。点击姓名或右键武将行进入“战斗详情 → 查看时间线”，或选中后点击按钮／双击。详情使用按 F 打开时的快照，按时间倒序列出本人作为来源或目标的击溃、负伤、单挑与被俘事件；地点取事件当时的棋格所属县府与当前城市。已核实的抓捕关联路径增加个人擒获与被俘计数，未匹配事件只保留候选。完整列顺序、零分母规则和持久化边界见 [0.8.3 本地说明](RELEASE_NOTES_0.8.3_LOCAL.md)。

0.8.4 的武将情报父开关统一暂停 F 入口与原生详情条，并保留两个子功能的选择。旧配置缺少父开关时默认开启。该界面调整不改变 F 快照频率或战绩计数口径。
